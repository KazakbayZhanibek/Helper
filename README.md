# Опыт мастера

Приложение превращает короткую запись работы в проверяемую инструкцию: автор загружает видео и готовит шаги, мастер проверяет и публикует, сотрудник открывает нужный фрагмент.

Реализованы **React / TypeScript / Vite + Django / DRF**, запись камеры, защищённая загрузка MP4/MOV/WebM, локальная обработка FFmpeg, ручной редактор и человеческая проверка. Есть локальная расшифровка whisper.cpp, текстовые предложения шагов и два визуальных режима: предварительные наблюдения камеры и отдельный анализ кадров сохранённого видео. Поддерживаются API-профили OpenAI `gpt-5.4-mini`, NVIDIA и OpenRouter. Для недорогой проверки подключён OpenRouter с `google/gemini-2.5-flash-lite` и накопительным пределом расходов. Локальный экспериментальный мост Codex CLI через подписку ChatGPT сохранён как отдельный профиль и не предназначен для публичного сервера. Первый сквозной тест настоящего видео пройден: ролик без звука длиной 20,96 с дал 4 подтверждённых по кадрам действия. Физическая камера и качество на наборе рабочих процессов ещё требуют проверки.

## Быстрый запуск

Нужны Python 3.12 и Node.js 24 с npm. Команды выполняются из корня репозитория. На этой машине рабочая папка: `/Users/janibek/Documents/ChatGPT/project #1226`.

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
npm --prefix frontend ci
cp .env.example .env
```

Если `.env` уже существует, сохраните его: повторное копирование заменит локальные настройки. Задайте в нём `DEMO_PASSWORD` длиной не менее 12 символов. Для локального запуска оставьте `DJANGO_DEBUG=1` и `DEMO_MODE=1`. `.env` исключён из Git.

Для просмотра собранной версии:

```sh
.venv/bin/python scripts/dev.py --preview
```

Откройте [главную страницу](http://127.0.0.1:4173). Она общая для посетителей; [вход](http://127.0.0.1:4173/login) ведёт в существующие рабочие пространства `/o/{org}/…`. Команда собирает интерфейс, применяет миграции, сохраняет существующие демоданные и запускает **API, веб-интерфейс и один processing worker**. `Ctrl+C` останавливает все три процесса. После изменения Python-кода или `.env` перезапустите команду.

Для разработки с Vite/HMR используйте `.venv/bin/python scripts/dev.py` и [порт 5173](http://127.0.0.1:5173). API слушает `127.0.0.1:8000`. Во встроенном браузере этой сессии подтверждён собранный preview; Dev/HMR отдельно не подтверждён. Если порт занят, остановите предыдущий запуск.

Для одной подготовки без серверов: `.venv/bin/python scripts/dev.py --prepare-only`. Launcher читает `.env`; прямой `manage.py` использует только уже экспортированные переменные и локальные значения по умолчанию. В каталоге с `#` Vite запускается через временную символьную ссылку — переименовывать рабочую папку не нужно.

## Видео и ИИ

[Первый пакет по аудиту воркера](docs/36-worker-efficiency.md): лёгкий опрос состояния, восстановление цикла после ошибок, пакетная очистка, индексы видеосессий и декодирование кадров до блокировки. Защита отмены перед внешним вызовом и при сохранении результата сохранена.

[OpenRouter](docs/34-openrouter-setup.md): подключены бесплатный профиль и Gemini 2.5 Flash-Lite с проверенным тарифом, потолком цены и накопительным лимитом расходов. Ключ задаётся только в локальном `.env`. Переключение модели не подтверждает улучшения распознавания; нужен одинаковый тест на исходных видео.

[План: мастер и новичок на одном сайте](docs/35-master-and-learner-plan.md) описывает два простых интерфейса и критерии качества видеоинструкций.

[Пояснения переработаны в рассказ о процессе](docs/33-process-story.md): для новых разборов ИИ объясняет этапы от лица мастера — что делаем, как и что меняется. В карточке основной текст расположен рядом с реальными фото; сведения о контактах, фазах и неясных моментах раскрываются отдельно. При применении сохраняется это же пояснение. Старые слова модели и применённая история не переписываются. Новых обращений к ИИ при доработке — 0.

Для реальных загрузок нужны FFmpeg и FFprobe. Для локальной речи — исполняемый `whisper-cli` и существующая GGML-модель `.bin`; приложение не скачивает модель автоматически. Без этих настроек остаётся ручной маршрут с учебным источником.

[Настройка видео, камеры, Whisper и облачного ИИ](docs/15-video-ai-setup.md) содержит переменные окружения, команду разрешения для организации, диагностику и сроки хранения кадров. Ключ выбранного провайдера хранится только на сервере: `NVIDIA_API_KEY` для NVIDIA или `STEP_DRAFT_API_KEY` для OpenAI. Текстовый генератор получает расшифровку; визуальный анализ получает **реальные JPEG-кадры** после отдельного согласия на передачу изображений. Полный видеофайл и аудиофайл этим провайдерам не отправляются. Для обоих режимов нужны серверный флаг и разрешение организации. [Локальный тест через Codex](docs/15-video-ai-setup.md#локальный-тест-через-codex-и-подписку-chatgpt) использует существующий вход ChatGPT без API-ключа, сохраняет согласия и ограничения и требует явного включения; в шаблоне он выключен.

Загружаются MP4/MOV и WebM камеры до 500 МиБ, длительностью 10 секунд–10 минут. Передача отображает фактический прогресс; после неё worker проверяет и готовит закрытую копию для просмотра. Камера требует localhost/HTTPS и разрешения браузера. Остановленную запись можно сохранить в IndexedDB этого браузера на 24 часа для восстановления под тем же аккаунтом в той же инструкции; переключатель можно отключить до записи. Это не защита от закрытия страницы во время самой записи. Предварительные наблюдения не добавляются в инструкцию. Без подключённого ИИ запись, загрузка и ручная разметка остаются доступны.

Визуальный анализ по умолчанию разбирает всю сохранённую запись: сначала все окна по 30 секунд, до 12 кадров в каждом, затем один уровень уточнений неясных мест окнами до 15 секунд. Можно выбрать отдельный фрагмент до 60 секунд. Звук не нужен. Перед запуском проверяется лимит на весь первичный обзор; перед каждым обращением атомарно резервируется бюджет. Прогресс показывает обработанные и пропущенные интервалы, готовые результаты сохраняются. Для камеры и проверки после настройки выбранного провайдера есть [пошаговый сценарий и приёмочный checklist](docs/15-video-ai-setup.md). Действия между кадрами могут быть пропущены, а таймкоды приблизительны: автор сверяет их с видео и подтверждает добавление или замену шагов. Публикация всегда выполняется человеком.

Сохранённое видео теперь проходит локальный обзор изменений и пакетное извлечение кадров. На тестовом ролике 62,88 с подготовка ускорилась с 11,44 до 4,13 с при сохранении лимита до 12 изображений на запрос. Это замер подготовки, без времени ответа ИИ. [Результаты, ограничения, метрики и воспроизводимый benchmark](docs/17-video-preparation-results.md).

## Что попробовать

1. Войти автором, создать инструкцию и загрузить разрешённый MP4/MOV/WebM, записать видео камерой либо выбрать синтетический учебный источник. Запись камеры нужно отдельно сохранить в инструкции.
2. Дождаться готовности видео. Добавить ручные шаги; при настроенном Whisper — запустить расшифровку. При подключённом облаке можно отдельно разрешить анализ кадров выбранного фрагмента.
3. Просмотреть предложение, источники и предупреждения. Текстовое предложение требует подтверждения замены; визуальное позволяет подтвердить добавление или замену. До применения рабочие шаги остаются прежними. Предварительные наблюдения камеры применить нельзя: после сохранения записи нужен новый анализ видео.
4. Сохранить и отправить инструкцию на проверку. Проверяющий отмечает каждый шаг и пять общих подтверждений, затем публикует или возвращает с причиной.
5. Войти читателем и открыть публикацию. Выбор шага перематывает видео, а воспроизведение запускается отдельно. Новый рабочий черновик не изменяет уже опубликованный снимок.

Состояние хранится в локальной SQLite-базе `backend/db.sqlite3`, файлы — в закрытом `backend/private-media/`; оба исключены из Git. Для восстановления остановленной камеры отдельно используется IndexedDB браузера; локальная копия удаляется после успешной загрузки или вручную, просроченная — при следующем открытии камеры. Контент не сохраняется в браузерный localStorage. Опубликованные версии неизменяемы, а конфликт ETag/If-Match не перезаписывает чужую ревизию.

## Границы текущей версии

Это работающая локальная реализация, ещё не выпуск D0/D1. Очередь хранится в БД и обслуживается одним последовательным worker; Celery/Redis в текущем запуске не используются. Нужны приглашения и восстановление пароля, управление участниками, блокирующие комментарии, обратная связь читателя, удаление и backup/restore, Nginx internal delivery, staging и полная приёмка устройств. Реализован внутренний ledger обращений и расходов с атомарным резервом на сеанс, организацию (день/месяц UTC) и платформу (день UTC). Проверенный денежный расчёт доступен только для OpenAI `gpt-5.4-mini`; неизвестный тариф блокирует запрос. Codex учитывается только в обращениях подписки, без выдуманной стоимости в долларах. Подключение платежей, утверждённые клиентские тарифы, кеш повторных анализов и приёмка реального платного billing остаются отдельными задачами.
