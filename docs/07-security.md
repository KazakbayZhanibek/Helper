# Доступ, данные и доверие к результату

[К полному плану](00-overview.md)

## Граница доступа

Публичный сайт с идеями и закрытый продукт — разные системы. Видеозаписи предприятия не наследуют настройку «всем по ссылке» от карты идей. В D0/D1 организация закрыта; регистрация только по приглашению. Демо использует собственные материалы и отдельную демонстрационную организацию.

| Действие | Reader | Author | Reviewer | Admin |
|---|---|---|---|---|
| Читать текущую публикацию, искать, отправлять замечание | Да | Да | Да | Да |
| Смотреть рабочие материалы организации | Нет | Да | Да | Да |
| Создавать/править черновики, запускать разрешённую обработку | Нет | Да | Да | Да |
| Отправлять на проверку/отзывать запрос | Нет | Да | Да | Да |
| Проверять шаги, возвращать, публиковать, отзывать публикацию | Нет | Нет | Да | Да |
| Приглашать, отключать, менять роли | Нет | Нет | Нет | Да |
| Менять лимиты в разрешённых пределах, удалять инструкцию | Нет | Нет | Нет | Да |
| Получать ключи провайдера или доступ к серверу | Нет | Нет | Нет | Нет |

Author видит все рабочие материалы своей организации. В D1 нет личных секретных папок между авторами одной компании. Если пилот требует доступ по цехам или подразделениям, это отдельное изменение модели до загрузки таких материалов. Admin организации не является системным оператором сервера.

## Авторизация на каждом запросе

1. Получить пользователя из серверной сессии.
2. Проверить active user, active membership и status organization.
3. Найти объект сразу с условием organization_id, затем проверить действие и lifecycle.
4. Проверить связанные объекты: asset, transcript, job, proposal, version, feedback.
5. Для reader дополнительно проверить наличие текущей публикации и право на связанный playback.
6. Сформировать только разрешённые поля; не отдавать всё и скрывать часть на клиенте.

Нельзя доверять organization из body, URL или UUID без membership. Нельзя использовать общий кэш ответа разных пользователей без учёта организации и доступа. В первой версии защищённые ответы и медиа получают private/no-store; публичный CDN для медиа отсутствует. Отсутствие membership и чужие объекты дают нейтральный 404, а известный свой объект с запрещённым действием — 403.

Отзыв membership запрещает следующий запрос. Уже полученные байты и сделанный пользователем скриншот отозвать технически невозможно. При длительной выдаче видео не обещать мгновенное прекращение открытого HTTP-потока; UI при следующем API/polling запросе завершает сессию чтения.

## Вход и приглашения

- Использовать Django password hashing и валидаторы; минимум 12 символов как исходное правило пилота, без собственного шифрования паролей.
- Session cookie: Secure, HttpOnly, SameSite=Lax; HTTPS в тестовом и рабочем окружении. Предлагаемый срок сессии — 12 часов, уточнить у пилота.
- CSRF проверяется для всех unsafe browser requests, включая login. После входа менять session key средствами Django.
- Приглашение хранит hash случайного токена, TTL 72 часа, email и роль; raw token отсутствует в логах. Совпадение email проверяется; существующий пользователь должен войти в свой аккаунт.
- Reset выдаёт одинаковый ответ для существующего и отсутствующего email. Токен одноразовый, TTL один час; смена пароля отзывает связанные старые сессии.
- Лимиты начального пилота: login 5 неудач/15 минут на комбинацию IP+email, reset 3/час на email, invite 20/час на организацию. Без постоянной блокировки, которую легко использовать для отказа в обслуживании.
- Оператор создаёт первую организацию и admin служебной командой. Общий пароль «для всех сотрудников» не используется.

Числа выше — настройки проектирования; проверить сценарий общего корпоративного NAT, чтобы лимиты по одному IP не блокировали всю команду.

## Загрузка и воспроизведение

Лимиты применяются на Nginx и в приложении. До передачи резервируются ожидаемые байты; во время передачи отслеживается фактический предел. Uploaded filename никогда не становится путём. Проверять symlink/path traversal, ложный MIME, большой поток без Content-Length, разрыв соединения, повтор session и повреждённый контейнер.

Файл сначала в quarantine вне web root. FFmpeg запускается непривилегированно с ограничениями; оригинал не открывается reader. Nginx internal path нельзя вызвать снаружи; API разрешает только серверный storage_key проверенного объекта. Проверить Range 206, недопустимый диапазон 416, HEAD и прямой обход internal URL. Thumbnail защищён теми же правами, что видео.

Наличие антивирусной проверки можно добавить после выбора среды, но нельзя называть файл безопасным только на основании её отсутствующих результатов. Основные меры D1 — ограниченный формат, изоляция декодирования, обновления и запрет публичной выдачи оригинала.

## ИИ и внешние поставщики

По умолчанию `external_ai_enabled=false`. Перед включением зафиксировать: кто разрешил данные, какие поля уходят, в какую страну/среду, каковы условия хранения, доступность удаления, бюджет и получатель счёта. Это рабочий список решений; юридическая допустимость реального договора требует отдельной проверки применимых требований, а не вывода из этого плана.

В D1 внешний поставщик получает только разрешённую расшифровку. Маскирование может снизить риск, но не гарантирует удаления всех персональных или коммерческих данных. Если компания не разрешает передачу текста, использовать ручной режим или отдельно согласованную локальную модель, измерив ресурсы и качество.

Любой текст видео, файл и ответ модели считаются недоверенными данными. Фразы «игнорируй правила», ссылки и похожие на системные команды строки не получают полномочий. Строгая схема и текстовая инструкция помогают, но не обеспечивают защиту сами по себе: генератор не имеет инструментов публикации, сетевых действий или доступа к другим компаниям. [OWASP Prompt Injection](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html).

Вывод модели отображается обычным текстом, без raw HTML. Если в будущем появится Markdown, использовать allowlist sanitizer; JavaScript URL и произвольные embed запрещены. В D1 пользовательские URL не загружаются сервером, поэтому генератору не нужен web fetch.

## Хранение и удаление

Предлагаемая политика пилота, которую необходимо показать владельцу данных до загрузки:

| Данные | Срок/правило |
|---|---|
| Незавершённая upload session | TTL 2 часа; уборка временных файлов не позднее 24 часов |
| Отклонённый оригинал | Закрыт сразу, физическое удаление в течение 24 часов |
| Оригинал и playback активной инструкции | До удаления инструкции; срок пересматривается с компанией |
| Временный WAV | Удаление после успешной ASR; при ошибке максимум 24 часа, повтор создаёт заново |
| Transcript, шаги, версии | Пока существует инструкция; сохраняются для проверки происхождения |
| Технические логи | 14 дней, без содержимого материалов |
| Audit события | 90 дней, минимальные метаданные |
| Резервные копии | 7 ежедневных поколений, закрытое зашифрованное хранилище |
| Tombstone удаления | Минимум 30 дней и дольше любого существующего backup, содержащего объект |

Удаление: немедленно скрыть объект и отозвать выдачу; отменить jobs; удалить активные файлы и производные максимум за 24 часа; пометить состояние удаления и повторять временный сбой. Старые закрытые backups истекают по своей политике в пределах семи дней. Пользователю нельзя писать «везде удалено» до исполнения этой политики. При восстановлении применить сохранённые вне откатываемого backup tombstones **до** открытия доступа.

Сроки не выдаются за требования законодательства. Если компания требует иной срок, регион хранения или подтверждённое удаление у поставщика, решение входит в договорённость пилота и влияет на архитектуру.

## Журнал и секреты

Логировать login outcome без пароля, изменение ролей, upload outcome, processing outcome, submit/return/publish/withdraw, deletion, external AI enable/disable и consumption. Допустимые metadata: IDs, коды, длительности, размеры, usage. Не писать prompt, transcript, токены приглашений, cookie, authorization header и provider key.

Секреты находятся в environment/секрет-хранилище сервера, не в Git, frontend bundle или Obsidian. `.env.example` содержит имена переменных и безопасные пустые значения. В тестах — специальные фиктивные ключи. Случайно опубликованный ключ отозвать и заменить; удаление строки из файла само по себе недостаточно.

## Что блокирует выпуск

Любая утечка между организациями; публичный оригинал; публикация без reviewer/admin; возможность подменить проверяющего; запись без разрешённого режима обработки; обход лимита платных вызовов; неработающее удаление; восстановление удалённого материала из backup. Эти проверки включены в задачи и [матрицу приёмки](08-quality.md).
