# Опыт мастера — полный план разработки

Версия 1.0 · 28 октября 2026 года · Казахстан, Asia/Almaty.

**Решение пользователя:** взять «Опыт мастера» за основу и начать подготовку разработки. **Результат первой версии:** компания может превратить короткую запись работы в проверенную инструкцию, а сотрудник — найти и открыть нужный шаг с телефона.

Документы ниже задают конкретный исходный проект. Числовые ограничения, состав пилота, технический стек и критерии выпуска — проектные решения и целевые значения, а не уже достигнутые результаты. Их меняют осознанно, обновляя связанные задачи и проверки.

## Что уже определено

1. Три постоянных участника; ещё шесть не включаются в обязательную мощность команды.
2. Проект развивается после декабря. Первая рабочая версия нужна для проверки реальной пользы.
3. Начинаем с адаптивного сайта; один интерфейс автора и другой режим для читателя работают в одном приложении.
4. Инструкции принадлежат организации. Доступ по приглашению; QR-код ведёт на обычную защищённую страницу.
5. До публикации черновик проверяет человек с правом публикации. ИИ не утверждает инструкцию.
6. Первая автоматизация опирается на речь мастера и её временную привязку. Полное распознавание молчаливых действий откладывается.
7. В первой версии есть ручное создание шагов: отказ ИИ не делает продукт бесполезным.
8. GPT‑6 Astra помогает писать и проверять код. Провайдер, модель и договорённости для ИИ внутри продукта выбираются отдельно; доступ к модели в рабочем приложении не доказывает наличие подходящего API.

## Что пока неизвестно

| Неизвестное | Временное решение | Когда решить |
|---|---|---|
| Навыки и часы каждого | Участники A, B, C; назначения предварительные | До обещания календарной даты партнёру |
| Компания для пилота | Одна команда комплектации/упаковки, как проверяемая гипотеза | Первый этап, T003 |
| Разрешённые записи | Только свои или согласованные материалы | До загрузки реальных рабочих видео |
| API для составления шагов | Адаптер, тестовый ответ и ручной режим; без передачи материалов по умолчанию | T004/T044 |
| Хостинг, место хранения, бюджет | Локальная разработка; закрытый тестовый сервер после решения владельца | T005/T053 |
| Качество казахской и смешанной речи | Набор отдельных проверочных записей; без обещаний качества | T043/T046 |
| Окончательный объём до декабря | Утверждается после оценки скорости первой недели | Контрольная точка 3 ноября |

Неизвестные коммерческие условия не мешают сделать редактор, права, тестовые данные и ручной сквозной сценарий. Реальные записи и платные вызовы зависят от конкретного решения владельца данных и бюджета.

## Три уровня результата

**D0 — рабочий ручной процесс.** Вход, организация, загрузка, видео, ручные шаги, проверка, публикация, чтение, поиск, права и удаление. Самостоятельно полезен и проверяется без внешнего ИИ.

**D1 — целевой пилот с ИИ.** D0 плюс расшифровка, автоматический черновик шагов, ссылки на исходные фрагменты, проверка качества и безопасные повторы обработки.

**D2 — развитие после пилота.** Вопросы по инструкциям, перевод, работа без сети, интеграции, несколько филиалов и расширенный жизненный цикл знаний. Отдельные решения после измерений D1.

## Первые действия

- A: уточнить задачу компании и сделать кликабельный маршрут редактора.
- B: создать основу сервера и модели организации, участников и инструкций.
- C: подготовить пять разрешённых видео и вручную разметить правильные шаги; проверить доступный способ расшифровки.
- Все: договориться о формулировке одного процесса, правилах хранения и о том, кто принимает готовую инструкцию.

Начинать реализацию по порядку задач T001–T009. Статусы задач остаются `pending` до фактической реализации и проверки. Завершение этого плана не означает завершение задач приложения.

## Схема продукта

```mermaid
flowchart LR
    A[Видео с пояснениями мастера] --> B[Проверка файла]
    B --> C[Подготовка видео и расшифровки]
    C --> D[Черновик шагов с источниками]
    B --> E[Ручная разметка]
    D --> F[Редактор]
    E --> F
    F --> G[Проверка человеком]
    G --> H[Опубликованная версия]
    H --> I[Поиск и просмотр с телефона]
    I --> J[Сообщение о проблеме]
    J --> F
```

## Как пользоваться документацией

Продуктовые решения задаёт 01, поведение экранов — 02, серверные инварианты — 04/05/07. При противоречии остановить зависимую реализацию и исправить документы в одном изменении. Не выбирать удобную трактовку молча. За контракт отвечает B, за сценарий A, за качество обработки C.

Рабочий оригинал документации находится в `master-experience/docs`. Копия в Obsidian предназначена для чтения и обсуждения; двусторонняя синхронизация не настроена. После согласованного изменения обновлять обе версии одной операцией.
