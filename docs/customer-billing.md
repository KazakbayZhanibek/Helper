# Подписки кухонь

Кухня начинает работу на бесплатном тарифе «Старт» и может хранить до пяти рецептов и пригласить участников в пределах трёх мест вместе с владельцем. Тариф «Команда» даёт 100 рецептов и 15 мест. При уменьшении лимита клиент сохраняет существующие рецепты, их версии и состав команды. Проверка лимита срабатывает при добавлении материала или участника. Общие инструкции, находившиеся в архиве до установки биллинга, начинают занимать место только при превращении в рецепт.

## Подготовка магазина

1. Зарегистрируйте магазин Dodo Payments для продажи цифровой подписки и пройдите проверку продавца для реальных оплат. Казахстан указан в политике приёма продавцов. [Условия Dodo Payments](https://docs.dodopayments.com/miscellaneous/merchant-acceptance).
2. В **Test Mode** создайте отдельный продукт с фиксированной периодической ценой, выберите валюту и интервал списаний. Каталог сайта читает базовую цену этого продукта через API. Скидки, местные налоги и итоговую сумму клиент видит перед подтверждением в платёжной форме. [Настройка подписки](https://docs.dodopayments.com/developer-resources/subscription-integration-guide).
3. Создайте ключ API в том же магазине и режиме. Нужны чтение продукта, платежа и подписки, создание и чтение checkout-сессий и создание сессии клиентского портала. Запишите идентификаторы магазина и продукта.
4. Создайте webhook с публичным HTTPS-адресом `/api/v1/billing/webhooks/dodo`. Включите события семейства `subscription.*`, в том числе `active`, `renewed`, `updated`, `past_due`, `on_hold`, `paused`, `unpaused`, `plan_changed`, `failed`, `cancelled` и `expired`. Скопируйте секрет подписи этого endpoint. Системные часы сервера должны быть синхронизированы. [Уведомления Dodo](https://docs.dodopayments.com/developer-resources/webhooks).
5. На сервере задайте переменные для API и укажите внешний URL приложения. После изменения конфигурации пересоздайте соответствующие контейнеры. Секреты вводятся только на сервере. В Docker Compose задайте значения в переменных с префиксом `RECIPE_DODO_` и домен в `RECIPE_HOST`. При прямом запуске Django используйте имена из таблицы.

| Переменная приложения | Значение |
| --- | --- |
| `DODO_MODE` | `test` для тестового магазина, `live` для реальных оплат |
| `DODO_BUSINESS_ID` | Идентификатор магазина |
| `DODO_PRODUCT_ID` | Идентификатор продукта «Команда» |
| `DODO_API_KEY` | Серверный API-ключ выбранного режима |
| `DODO_WEBHOOK_SECRET` | Секрет подписи соответствующего webhook |
| `APP_PUBLIC_URL` | Внешний адрес сайта для возвращения в кабинет кухни |

## Проверка перед продажами

Зарегистрируйте тестовую кухню, подтвердите email администратора и откройте подписку. Проверьте валюту и интервал списаний. Оформите покупку тестовым способом оплаты провайдера. После подтверждения у кухни должен появиться тариф «Команда». В клиентском кабинете проверьте доступ к счёту и отмену. Если отмена запланирована на конец периода, тариф действует до указанной даты. [Платёжная форма Dodo](https://docs.dodopayments.com/developer-resources/checkout-session).

Подписка привязана к кухне по идентификатору, который сервер записал при создании оплаты. Повторная доставка одного webhook обрабатывается однократно. Просроченное уведомление не заменяет более свежее состояние. Если подтверждение задержалось, администратор может обновить оплату. Сервер проверит сессию оформления, платёж и подписку в Dodo. Возврат браузера на сайт сам по себе не открывает платные возможности.

Личный платёжный кабинет доступен администратору, который оформил подписку. В Dodo создаётся отдельный покупатель для этого оформления. Доступ других администраторов кухни к рецептам не открывает им платёжные документы покупателя. [Клиентский портал](https://docs.dodopayments.com/api-reference/customers/create-customer-portal-session).

Для реальных продаж отдельно настройте live-продукт, авторизацию и webhook в одобренном магазине, затем выставьте `DODO_MODE=live`. Тестовые события и подписки хранятся отдельно от реальных. Оплата подписки управляет лимитами рецептов и участников. Бюджет внешнего ИИ проверяется в отдельном контуре и не увеличивается при оформлении подписки.
