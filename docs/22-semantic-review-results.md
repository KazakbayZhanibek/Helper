# Повторная проверка действий: реализация и пределы качества

2 ноября 2026 · Asia/Almaty. Добавлен отдельный проход сопоставления учебного черновика с кадрами. **Автоматический запуск выключен: четыре реальных проверки не подтвердили устойчивого улучшения, оправдывающего дополнительный расход.** Учебный формат v3 остаётся включён в локальном пилоте.

## Реализация

`VisualReviewProvider` получает те же изображения и явно неподтверждённого кандидата. Он может исправить, исключить или добавить наблюдение, но его ответ по-прежнему проходит обычную проверку v3 и требует проверки мастером. Повторение исходного текста не считается доказательством. Вход, схема и инструкция ограничены 32 KiB; ответ также ограничен 32 KiB. До 12 JPEG, прежняя модель `gpt-6-luna`, reasoning `medium`. Никаких скрытых дополнительных запросов внутри провайдера.

Режим `VISUAL_SEMANTIC_REVIEW=1` закрепляется только при создании нового upload-сеанса v3; live и старые сеансы не переключаются. Сейчас **и локальный `.env`, и `.env.example` содержат `VISUAL_SEMANTIC_REVIEW=0`**. Его включение пока предназначено для разработки, не для обычного использования.

Worker сначала заканчивает первичный просмотр всей записи. Затем, если режим включён, проверяет и уверенно сформулированные действия: ошибочное утверждение может не содержать предупреждения. Каждый проход использует отдельный `verify:<window_id>` и тот же реестр лимитов сеанса, организации и платформы. При отсутствии остатка проверка пропускается, первоначальный результат сохраняется с предупреждением. Дополнительные плотные выборки планируются только при достаточном остатке и на их проверки. Лимиты не увеличиваются.

Миграция `0005_semantic_review` создаёт отдельную запись `VisualAnalysisReview`. Завершённое первичное окно неизменно. Проверка имеет контрольную точку до отправки; прерванный запрос не повторяется при восстановлении задания. Завершённая проверка неизменна на уровне БД. Если она исключила все действия, пустой результат не заменяется более длинным исходным ответом. При сбое остаётся исходный непроверенный кандидат. Применения и публикации автоматически нет.

В учебных карточках блок «Уточнить по записи» теперь находится непосредственно после объяснения шага. Он показывает существующие пробелы с общими UUID кадров и открывает соответствующий фрагмент; совпадение времени само по себе не используется. Отсутствие такого блока не означает, что действие достоверно. [Снимок интерфейса](../artifacts/test-results/semantic-review-inline-gaps.jpg).

## Четыре обращения, три процесса

Новый эксперимент `semantic-grounding-v1` имеет отдельный общий предел **4 обращения**, включая другие отчёты и перезапуски. Предыдущий `teaching-video-v1` остаётся исчерпанным: его лимит и история не сбрасывались. Новый эксперимент завершён: **4 settled / 0 held**. Платный API не использовался; расход и остаток токенов подписки в доллары не переводились.

Проверялись сохранённые ошибочные кандидаты, а не новая генерация полного двухпроходного задания. На каждое обращение переданы точные 12 JPEG прежней выборки с теми же таймкодами. UUID переназначены проверяемым соответствием хэша, размера и времени. Все 48 хэшей проверены. Исходные рабочие копии остались прежними, предложения не применялись и не публиковались.

| Исходный кандидат | Новая проверка | Содержание по заранее записанным критериям |
|---|---:|---|
| Последний шуруповёрт с выдуманной установкой бруска | 19,95 с | Установка исключена, видимое вкручивание и отвод сохранены. Остались неподтверждённое исходное состояние и неверный охват отвода action-кадрами. PARTIAL. |
| Замес | 24,50 с | Повороты и прижатия сохранены. Первоначальное внесение готового теста опять осталось состоянием и вопросом, а не воспроизводимой операцией. PARTIAL. |
| Ранний шуруповёрт с ложным завершением скрытой операции | 16,48 с | Ложный результат на 12,866 с сохранён: инструмент ещё у бруска, хотя текст говорит, что он отведён. В пробеле появились неподтверждённые «следующий шуруп» и перемещение бруска. FAIL. |

Итого **2 PARTIAL, 2 FAIL, 0 PASS**. Корректность JSON, число шагов и повелительное наклонение не являлись критерием качества. Оценку выполнял отдельный агент, не писавший reviewer/backend; он участвовал в UI и знал исходные ошибки. Это не слепая оценка и не экспертиза мастера. [Критерии до запуска](../artifacts/test-results/teaching-independent-audit-v1.json), [подробная независимая оценка](../artifacts/test-results/semantic-grounding-independent-audit-v1.json).

Указано время только дополнительного обращения с готовыми кадрами, без загрузки и извлечения. Оно **добавляет примерно 16–25 секунд** к первоначальному анализу в этих четырёх пробах; ускорение не подтверждено. Проверка той же моделью способна повторить исходную ошибку и добавить новую. Поэтому запуск для каждого видео сейчас невыгоден, даже при соблюдении общего лимита.

Raw-отчёты: [последний шуруповёрт](../artifacts/test-results/semantic-grounding-current-drill-v1.json), [замес](../artifacts/test-results/semantic-grounding-initial-v1.json), [ранний шуруповёрт и нарезка](../artifacts/test-results/semantic-grounding-additional-v1.json). Между вторым и третьим обращением исправлена регистрация метрик для встроенного worker-прохода и дополнен список файлов в отпечатке runner; reviewer prompt, схема и модель не менялись. Новый файл отчёта сохранил общий остаток лимита.

## Проверки и результат для проекта

**546 backend-тестов прошли**, [вывод](../artifacts/test-results/semantic-review-backend.txt). В том числе реальный бюджетный реестр с подменёнными моделями проверяет общий лимит, все overview до проверки, запрет повторов после сбоя, неизменность оригинала, выбор пустого исправления, чужие UUID, закрепление режима и проверку уточнений. Django check и проверка отсутствия незафиксированных миграций прошли. **57 frontend-тестов**, TypeScript и production build прошли; после изменения порядка блоков сборка повторена.

В приложении доступны новый показ вопросов и четыре отдельные тестовые предложения. Автоматический второй проход не включён. Основная нерешённая задача — извлекать короткие действия и точные состояния из кадров без домысливания; ещё один общий запрос той же модели эту задачу не решил. Следующий осмысленный эксперимент должен менять наблюдаемость короткого действия или способ его разбора, а не только просить модель перепроверить собственный текст.

API, preview на 4173 и последовательный worker перезапущены с новой версией. В настоящем интерфейсе проверены порядок учебных полей, вопросы и переход: кнопка вопроса закрыла диалог и установила видео на 0,9 с без запуска анализа. Исходные рабочие шаги не изменялись. Проверка документации прошла.
