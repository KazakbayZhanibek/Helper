# Настройка видео, камеры и ИИ

1 ноября 2026 · Asia/Almaty · локальная разработка. Реализация: [медиа-контракт](../research/14-media-contract.md), [ASR/ИИ-контракт](../research/15-ai-contract.md), [камера и визуальный анализ](../research/16-visual-contract.md). Здесь нет ключей, паролей или содержимого рабочего `.env`.

## Два визуальных сценария

| Сценарий | Что происходит | Как результат попадает в инструкцию |
|---|---|---|
| Камера во время работы | Браузер записывает видео локально. После отдельного согласия передаёт уменьшенные JPEG; ИИ показывает предварительные наблюдения по выборке кадров | Live-наблюдения применить нельзя. Остановите запись, сохраните её в инструкции и запустите новый анализ сохранённого видео |
| Уже снятое видео | Worker готовит файл; по умолчанию разбирает всю запись окнами по 30 секунд / до 12 кадров, затем уточняет неясное окнами до 15 секунд в пределах бюджета | Автор смотрит кадры и полную запись, уточняет приблизительные таймкоды и подтверждает добавление или замену шагов |

Звук для обоих визуальных режимов не нужен. Это анализ отдельных изображений: быстрые действия между кадрами могут быть пропущены. Модель не получает непрерывный видеопоток; время ответа зависит от очереди и облачного провайдера.

Отдельно доступен путь по речи: сохранённое видео → локальный WAV → whisper.cpp → расшифровка с таймкодами → текстовое предложение шагов. Его можно использовать независимо от визуального анализа. Предложение любого типа требует просмотра и явного применения; проверка мастером и публикация остаются отдельными действиями.

## Что передаётся провайдеру

| Режим | Данные облачного запроса |
|---|---|
| Текстовые шаги | Текст сегментов расшифровки, их UUID, порядок и таймкоды, язык, длительность и идентификатор/ревизия расшифровки |
| Визуальные шаги / live-наблюдения | Реальные JPEG-кадры, их UUID, порядок, время, язык и режим анализа |

Whisper обрабатывает звук локально. Полный видеофайл, аудиофайл, абсолютные файловые пути и пароль пользователя в облачные запросы не входят. Кадры отправляются только после отдельного согласия на изображения, при включённом внешнем ИИ на сервере и в организации. Разрешение браузера на камеру само по себе не включает облачный анализ.

Для локальной проверки выбран тестовый адаптер Codex CLI с `gpt-6-luna` и существующим входом через ChatGPT. Это облачная обработка OpenAI в пределах доступных лимитов подписки, а не локальная модель или безлимитный режим. Вход и запросы выполняет установленный CLI; приложение не извлекает и не копирует `auth.json` и не переиспользует его токены как API-ключ.

Прямые API-адаптеры сохранены: OpenAI с [GPT-5.4 mini](https://developers.openai.com/api/docs/models/gpt-5.4-mini) и NVIDIA API Catalog с [мультимодальным API](https://docs.api.nvidia.com/nim/reference/nvidia-nemotron-3_5-super-vl-120b-a12b-infer). Они требуют собственного API-доступа. Адаптеры передают ограниченные выборки JPEG; смена провайдера не превращает их в непрерывное видео. Денежный расчёт сейчас проверен только для OpenAI `gpt-5.4-mini`; NVIDIA-запрос блокируется до добавления проверенных тарифов/usage, даже если ключ настроен.

Для OpenAI используется серверный `STEP_DRAFT_API_KEY`, для альтернативного NVIDIA — отдельный `NVIDIA_API_KEY`. Ключи не взаимозаменяемы. OpenAI-запрос содержит `store:false`; это не универсальное обещание отсутствия хранения у провайдера. Условия обработки и доступность выбранного сервиса проверяются отдельно.

## Подготовка

Установите зависимости по [README](../README.md). Для загрузки и анализа сохранённого видео нужны уже установленные FFmpeg/FFprobe. Для речи дополнительно нужны `whisper-cli` и multilingual-модель Whisper в GGML-формате `.bin`, например `ggml-small.bin`. Python lock-файл не устанавливает эти бинарники и не скачивает ASR-модель. Визуальный анализ не требует Whisper.

Проверьте исполняемые файлы:

```sh
command -v ffmpeg
command -v ffprobe
ffmpeg -version
ffprobe -version
```

Если бинарники находятся вне `PATH`, используйте их реальные абсолютные пути. Ниже `/absolute/path/to/...` обозначает место для замены, а не существующий путь проекта.

## Переменные окружения

Скопируйте `.env.example` в `.env` только при первой настройке. В существующем файле меняйте нужные строки, сохраняя локальный пароль и остальные настройки.

Шаблон по умолчанию оставляет API-профиль OpenAI и выключает внешний ИИ и тестовый мост Codex. Общие настройки и прямой API-профиль:

```dotenv
DJANGO_DEBUG=1
DEMO_MODE=1
DEMO_PASSWORD=

FFMPEG_PATH=/absolute/path/to/ffmpeg
FFPROBE_PATH=/absolute/path/to/ffprobe
VIDEO_FRAME_STRATEGY=events
ASR_BACKEND=whisper_cpp
WHISPER_CPP_BINARY=/absolute/path/to/whisper-cli
ASR_MODEL_PATH=/absolute/path/to/ggml-small.bin
ASR_NO_GPU=1

STEP_DRAFT_BACKEND=openai
STEP_DRAFT_ENDPOINT=https://api.openai.com/v1
STEP_DRAFT_MODEL=gpt-5.4-mini
STEP_DRAFT_API_KEY=
NVIDIA_API_KEY=
EXTERNAL_AI_ENABLED=1

CSRF_TRUSTED_ORIGINS=http://127.0.0.1:5173,http://localhost:5173,http://127.0.0.1:4173,http://localhost:4173
```

`DEMO_PASSWORD` — локальный пароль из 12+ символов. Для прямого OpenAI API заполните `STEP_DRAFT_API_KEY` на сервере; ключ не нужно присылать в чат, записывать в документацию или помещать в frontend. Не копируйте NVIDIA-ключ в поле OpenAI. Один комплект `STEP_DRAFT_BACKEND`/`STEP_DRAFT_ENDPOINT`/`STEP_DRAFT_MODEL` используется текстовым и визуальным адаптерами; модель должна принимать изображения и поддерживать структурированный ответ. Пустой ключ прямого API оставляет его текстовый и визуальный режимы недоступными.

Название модели в конфигурации не подтверждает доступ аккаунта. Приложение проверяет комплект настроек, а подлинность ключа и возможность вызова выясняются при выполнении реального задания. Указанный пользователем баланс $50 в NVIDIA не проверялся и не используется адаптером OpenAI.

Чтобы вернуться к NVIDIA, замените только облачный блок и используйте его собственный ключ:

```dotenv
STEP_DRAFT_BACKEND=nvidia
STEP_DRAFT_ENDPOINT=https://integrate.api.nvidia.com/v1
STEP_DRAFT_MODEL=nvidia/nemotron-3.5-super-vl-120b-a12b
NVIDIA_API_KEY=
```

При этом `STEP_DRAFT_API_KEY` не используется. `ASR_NO_GPU=1` относится только к локальному whisper.cpp: он запускает распознавание без GPU; убрать его можно после проверки подходящего GPU runtime.

В `.env.example` внешний ИИ выключен по умолчанию. При `EXTERNAL_AI_ENABLED=0` или недоступном выбранном провайдере доступны запись камеры, скачивание, загрузка и ручная разметка. Запись не подменяется демонстрационным результатом ИИ.

## Локальный тест через Codex и подписку ChatGPT

Этот мост предназначен только для доверенного локального запуска на `127.0.0.1`. Для публичного сервера или пользователей организации используйте API-адаптер и отдельный серверный ключ. Требуются установленный Codex CLI, существующий вход через ChatGPT и доступ к выбранной модели в подписке. Проверьте вход командой `codex login status` либо той же командой с полным путём к установленному бинарнику; если вход отсутствует, выполните обычный интерактивный `codex login` самостоятельно. Не переносите файлы авторизации в проект.

Для включения замените профиль в существующем `.env`, сохранив настройки медиа:

```dotenv
DJANGO_DEBUG=1
DEMO_MODE=1
STEP_DRAFT_BACKEND=codex
STEP_DRAFT_MODEL=gpt-6-luna
CODEX_TEST_MODE=1
CODEX_CLI_BINARY=/absolute/path/to/codex
EXTERNAL_AI_ENABLED=1
```

`CODEX_CLI_BINARY` должен указывать на реальный исполняемый файл. Например, проверенный встроенный путь macOS: `/Applications/ChatGPT.app/Contents/Resources/codex-cli/CodexCLI.app/Contents/MacOS/codex`. `STEP_DRAFT_ENDPOINT`, `STEP_DRAFT_API_KEY` и `NVIDIA_API_KEY` в режиме `codex` не используются; сохранённые ключи удалять не нужно.

Адаптер запускает отдельный `codex exec`: временная рабочая папка, read-only sandbox, отключённые инструменты и пользовательские конфигурации, обязательный вход ChatGPT, JSON Schema и проверка ответа приложением. API-ключи не передаются процессу. Таймаут одной попытки — 180 секунд; очередь поддерживает отмену и проверяет состояние до сохранения результата. Внешний ИИ на сервере, разрешение организации и отдельное согласие на изображения по-прежнему обязательны.

Официальные механизмы: [non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode) и [параметры Codex CLI](https://learn.chatgpt.com/docs/cli/reference). Это временная проверка продукта через персональную подписку: доступность, очередь и лимиты могут задержать или отклонить запрос. Перезапустите весь launcher после выбора режима. Чтобы выключить мост, задайте `CODEX_TEST_MODE=0` и верните API-профиль; автоматического перехода между провайдерами нет. Доказательства и ограничения — в [отчёте тестового режима](../research/18-codex-test-mode.md).

## Разрешение для организации

Внешняя передача требует двух флагов: серверного `EXTERNAL_AI_ENABLED=1` и `organization.external_ai_enabled`. Дополнительно автор подтверждает передачу изображений в выбранном визуальном сценарии. Для учебной организации в локальной SQLite-базе:

```sh
.venv/bin/python backend/manage.py configure_ai \
  --organization 7ea2d071-f15f-4fe9-b440-f1622b3e17cf \
  --allow-external
```

Для отмены разрешения:

```sh
.venv/bin/python backend/manage.py configure_ai \
  --organization 7ea2d071-f15f-4fe9-b440-f1622b3e17cf \
  --disable-external
```

Команда меняет только флаг организации и создаёт audit-событие; ключи она не принимает и не выводит. Для другой базы предварительно экспортируйте её переменные окружения и укажите UUID нужной организации. Прямой `manage.py` не загружает `.env` автоматически. В локальной учебной организации внешняя обработка разрешена. Это разрешение не подтверждает готовность ключа, подписки или модели.

## Запуск всех процессов

Из корня проекта:

```sh
.venv/bin/python scripts/dev.py --preview
```

Откройте [общую главную на порту 4173](http://127.0.0.1:4173), затем [вход](http://127.0.0.1:4173/login). Рабочие пространства остаются по маршрутам `/o/{org}/…`. Launcher читает `.env`, собирает интерфейс и запускает Django API, веб-интерфейс и один `processing_worker`. После изменения `.env` или Python-кода остановите весь launcher через `Ctrl+C` и запустите снова. Затем нажмите «Проверить подключение» в интерфейсе.

Отдельная команда worker существует для окружения с уже экспортированными настройками:

```sh
.venv/bin/python backend/manage.py processing_worker
```

`--once` обрабатывает не более одного ожидающего задания и завершает процесс. В SQLite запускайте только один worker: не запускайте дополнительный рядом с launcher. Очередь находится в БД; lease, heartbeat и проверка перед фиксацией защищают от позднего результата отменённой попытки. Celery/Redis не используются в этом локальном запуске. PostgreSQL-конкурентность ещё требует проверки.

## Снять процесс камерой

1. Создайте инструкцию и выберите «Камера · записать процесс». На следующем экране камера ещё выключена.
2. Выберите, нужен ли микрофон, и нажмите «Включить камеру» либо «Включить камеру и микрофон». Разрешите доступ в браузере. Нужны localhost или HTTPS, доступное устройство и поддержка MediaRecorder. Отказ доступа не мешает загрузить готовый файл.
3. В предпросмотре подтвердите право использовать запись. До начала можно отключить сохранение остановленного файла в этом браузере для восстановления; на общем компьютере это предпочтительно. При подключённом визуальном ИИ отдельно включите согласие на передачу кадров. Без него запись останется локальной до явной загрузки.
4. Нажмите «Начать запись». При выбранном наблюдении ИИ браузер передаёт JPEG не чаще одного раза в 2 секунды и запрашивает анализ не чаще одного раза в 8 секунд, когда предыдущее задание завершено. При сбое передачи повторяется тот же кадр с тем же ключом; номер увеличивается только после подтверждения сервера.
5. Наблюдения предварительные. Они не меняют рабочие шаги. Время на кадрах отсчитывается от подключения live-наблюдения после создания сеанса и не совпадает обязательно со временем видеозаписи.
6. Нажмите «Остановить запись». Камера и микрофон выключаются, передача кадров останавливается, поздний результат отменённого задания не сохраняется. Просмотрите файл, скачайте его или нажмите «Сохранить видео в инструкции».
7. Дождитесь подготовки сохранённого видео, затем используйте «Распознать действия по видео» по инструкции ниже. Это новый анализ с кадрами и временем из сохранённого источника.

Запись ограничена 10 минутами и 500 МиБ. Для загрузки нужны минимум 10 секунд; более короткий фрагмент можно скачать. Браузер выбирает поддерживаемый WebM или MP4. При включённом сохранении **после остановки** файл попадает в IndexedDB этого браузера. Откройте камеру той же инструкции под тем же аккаунтом и восстановите найденную запись в течение 24 часов; камера и ИИ от этого не включаются. Копия удаляется после успешной загрузки или вручную, а просроченные копии — при следующем открытии камеры. Если хранилище недоступно/заполнено, скачайте запись перед закрытием; при конфликте двух вкладок существующий файл не перезаписывается. Закрытие вкладки во время самой записи не покрыто восстановлением.

## Разобрать загруженное или сохранённое видео

1. Загрузите разрешённый MP4/MOV/WebM либо сохраните запись камеры. Подтвердите право использовать видео и согласие людей в кадре. Допустимы 10 секунд–10 минут, до 500 МиБ, один видеопоток: H.264/HEVC в MP4/MOV или VP8/VP9 в WebM. Необязательный звук — AAC/PCM для MP4/MOV или Opus для WebM.
2. Дождитесь передачи и подготовки. Процент относится к переданным байтам. Докачки с середины нет; worker отдельно проверяет контейнер, кодеки, разрешение и длительность и создаёт защищённую копию для просмотра.
3. По умолчанию выбрана вся запись: сначала все обзорные окна по 30 секунд / до 12 кадров, затем один уровень уточнений неясных мест до 15 секунд. Можно переключиться на отдельный фрагмент до 60 секунд. Задайте предел обращений и, для проверенного API-профиля, USD. Preflight проверяет весь первичный обзор; при недостаточном лимите запуск запрещён. Общий бюджет не резервируется заранее целиком: каждый вызов проходит отдельную атомарную проверку, поэтому при параллельном расходе анализ может остановиться с сохранёнными результатами.
4. Подтвердите отправку кадров этого фрагмента облачному ИИ и запустите анализ. Речь и расшифровка не обязательны. Пока результат готовится, рабочие шаги не меняются.
5. Откройте «Посмотреть действия и кадры». Посмотрите число обработанных окон, пропущенные интервалы и использованный бюджет. Сверьте каждое действие с кадрами и полной записью. Минимум два кадра связывают предложение с источником, но сами по себе не доказывают все движения между ними. Таймкоды вычисляет сервер из выборки; они приблизительны и требуют уточнения.
6. Выберите добавление после текущих шагов или замену всех текущих шагов и подтвердите применение. При существующих шагах интерфейс предлагает добавление. Общий предел рабочей инструкции — 30 шагов; результат из большего числа наблюдений сохраняется целиком, но применить его нельзя. Разделите материал или перенесите нужное вручную. Отметки проверки сбрасываются в обоих режимах. Изменение исходной рабочей ревизии делает предложение устаревшим.
7. Уточните текст и время в редакторе, сохраните и отправьте мастеру. Публикация возможна после обычной проверки человеком.

После обновления страницы сохранённые визуальные предложения доступны в истории. Применённый ответ можно открыть вместе с кадрами как исходный результат ИИ; это не повторное применение и не перезапись последующих правок. Приблизительность интервалов сохраняется даже при показе точных миллисекунд.

Если шагов нет или ответ отклонён, выберите другой фрагмент/ракурс либо разметьте запись вручную. Ошибка ИИ не стирает видео и существующие шаги. Готовые окна сохраняются. Уточнение заменяет исходное наблюдение только если все его дочерние окна завершены и дали уверенные шаги; иначе остаётся исходный обзор. При неизвестном исходе уже отправленный логический вызов автоматически не повторяется; запасного провайдера нет.

## Дополнить шаги по речи

У готового видео со звуком запустите распознавание речи. Whisper создаст новую неизменяемую ревизию расшифровки с сегментами и таймкодами. Просмотрите её, затем отдельно запросите текстовое предложение. Подтверждение применения текстового предложения заменяет рабочие шаги, поэтому сначала проверьте результат и текущую ревизию.

Без звука или разборчивой речи доступны визуальный анализ и ручная разметка. Для `kk` и `mixed` качество ещё не измерено; интерфейс отмечает их экспериментальными.

## Диагностика

```sh
.venv/bin/python scripts/check_pipeline.py
```

Для другой организации:

```sh
.venv/bin/python scripts/check_pipeline.py --organization UUID
```

Команда сама загружает `.env` и сообщает готовность FFmpeg/FFprobe, ASR, текстового генератора, `visual_analysis` и количество queued/running/failed jobs. Она не выполняет облачных запросов и не выводит секреты. `available:true` для облака означает комплект настроек, а не успешную проверку ключа или модели.

В интерфейсе автора также показываются причины недоступности из защищённых API:

```text
GET /api/v1/orgs/{organization_id}/ai-capabilities
GET /api/v1/orgs/{organization_id}/visual-capabilities
```

| Наблюдение | Что проверить |
|---|---|
| Задание остаётся `queued` | Запущен ли worker; после изменения `.env` перезапущены ли API и worker вместе |
| Камера не включается | Разрешение браузера, localhost/HTTPS, доступность устройства; попробуйте без микрофона или загрузите готовое видео |
| `MEDIA_RUNTIME_UNAVAILABLE` | Пути `FFMPEG_PATH`/`FFPROBE_PATH`, исполняемость файлов |
| `ASR_UNAVAILABLE` / `ASR_PROCESS_FAILED` | Локальный бинарник, существующая совместимая модель, права чтения; при проблеме GPU — `ASR_NO_GPU=1` |
| `NO_AUDIO` / `NO_SPEECH` | Наличие разборчивого звука; можно использовать визуальный анализ |
| Внешний ИИ отключён | Серверный флаг и разрешение конкретной организации |
| «Не настроен API-ключ» / `AI_AUTH_FAILED` | Ключ в серверной конфигурации, доступ к проекту и модели; перезапустите launcher |
| Тестовый Codex недоступен | `CODEX_TEST_MODE=1`, `DJANGO_DEBUG=1`, `DEMO_MODE=1`, исполняемый `CODEX_CLI_BINARY` и существующий вход ChatGPT через `codex login status` |
| Codex отклонил запрос или истёк таймаут | Доступная модель и лимиты подписки, соединение; 180 секунд — предел попытки, а не гарантия скорости |
| `IMAGE_CONSENT_REQUIRED` | Подтверждено ли отдельное согласие на отправку изображений |
| `INVALID_VISUAL_WINDOW` | Для window нужны границы внутри записи до 60 секунд; для full границы не задаются |
| `AI_BUDGET_TOO_SMALL` / `AI_BUDGET_EXCEEDED` | Лимит должен покрывать первый обзор и общие квоты; готовые результаты сохранены |
| `AI_PRICING_UNAVAILABLE` | Нет проверенной цены модели/endpoint: платный запрос заблокирован |
| `AI_CALL_OUTCOME_UNKNOWN` | Ранее отправленный вызов не повторяется автоматически; требуется сверка, резерв удерживается |
| `VISUAL_SESSION_CLOSED` | Live-сеанс остановлен или истёк; для наблюдения нужен новый сеанс |
| `VISUAL_CALL_LIMIT` / `VISUAL_STORAGE_QUOTA` | Лимит вызовов сеанса или хранения кадров; сроки очистки описаны ниже |
| `AI_RATE_LIMITED` / `AI_PROVIDER_UNAVAILABLE` | Лимиты/доступность провайдера; рабочие материалы сохраняются |
| `STALE_PROPOSAL` / 412 | Рабочая версия или источник изменились; сохраните правки и запросите новое предложение |
| `MODEL_OUTPUT_INVALID` / `VISUAL_OUTPUT_INVALID` | Ответ не прошёл проверку структуры/источников; он не применяется к шагам |
| 403 CSRF в preview | Разрешён ли фактический origin с портом 4173 и перезапущен ли API |

Проверки кода выполняются `make check`. Не включайте пароли, `.env`, Authorization/cookie, полные расшифровки, JPEG или ответы провайдера в технические логи.

## Хранение кадров и ограничения

Live-сеанс действует до 10 минут, принимает до 300 кадров по 512 КиБ с максимальной стороной после подготовки 960 px. Сервер принимает не более одного нового кадра в секунду; интерфейс передаёт раз в 2 секунды. В анализе участвуют максимум 12 кадров, не чаще одного обращения в 8 секунд и максимум 60 вызовов ИИ за live-сеанс, включая повторы. Эти технические пределы дополнены ledger-квотой сеанса по умолчанию 30 обращений и общими квотами организации/платформы. План 30 секунд / 20 вызовов live ещё не внедрён. На организацию допускаются до трёх активных камер и 512 МиБ сохранённых кадров.

Worker примерно раз в минуту запускает ограниченную очистку. При истечении активного сеанса ожидающие задания отменяются, выполняющиеся получают запрос отмены. Неиспользованные live-кадры удаляются не ранее чем через час после `expires_at`; кадры upload-сеансов — через 7 суток от создания сеанса. Очистка пропускает активные задания и сеансы с применёнными предложениями. Применённые кадры-основания сохраняются вместе с инструкцией. Текст наблюдений и полная видеозапись этой очисткой не удаляются.

Отдельный запуск той же очистки, для уже настроенного окружения:

```sh
.venv/bin/python backend/manage.py cleanup_visual_sessions
```

Команда выполняет ограниченную порцию работы; просроченные кадры могут сохраняться дольше при остановленном worker, наличии активного задания или очереди очистки. Это не полное удаление данных организации.

Текстовый запрос ограничен 300 сегментами / 18 000 символами, результат прямых API-адаптеров — 8192 completion tokens. Для Codex действует таймаут 180 секунд и лимиты подписки; API-лимит токенов не является обещанием аналогичного ограничения CLI. Реализованы ledger, атомарный резерв до каждого внешнего вызова, settlement по usage и удержание unknown. Лимиты и переменные описаны ниже. Денежный расход реального платного API ещё требует отдельной приёмки.

## Серверные лимиты ИИ

Все настройки есть в `.env.example`. Денежные величины — целые USD microdollars: 1 USD = 1 000 000. `AI_BUDGET_ENABLED=0` блокирует новые вызовы, а не разрешает работать без учёта.

| Настройка | Значение по умолчанию |
|---|---|
| `AI_BUDGET_DEFAULT_CALLS` / `AI_BUDGET_MAX_CALLS` | 30 / 60 на сеанс |
| `AI_BUDGET_ORG_DAY_CALLS` / `AI_BUDGET_ORG_MONTH_CALLS` | 100 / 2 000 |
| `AI_BUDGET_PLATFORM_DAY_CALLS` | 500 |
| `AI_BUDGET_DEFAULT_MICROUSD` / `AI_BUDGET_MAX_MICROUSD` | 2 000 000 / 5 000 000 ($2 / $5 на сеанс) |
| `AI_BUDGET_ORG_DAY_MICROUSD` / `AI_BUDGET_ORG_MONTH_MICROUSD` | 10 000 000 / 100 000 000 ($10 / $100) |
| `AI_BUDGET_PLATFORM_DAY_MICROUSD` | 50 000 000 ($50) |

Периоды организации и платформы считаются в UTC. Денежный профиль — только `openai/gpt-5.4-mini` на официальном endpoint; верхний резерв одного 12-кадрового запроса — $0,072696. Это консервативный предел, не фактический чек. Codex показывает subscription_calls, локальный Ollama — local_calls, деньги null. Неизвестный тариф/модель/endpoint, включая NVIDIA без тарифного адаптера, блокирует запрос. Подробный расчёт и границы — в [модели бюджета](04-data.md#реализованный-бюджет-и-проект-экономики).

Ошибочный JSON, отмена или потеря lease не означают бесплатный запрос. Receipt учитывается независимо от состояния задания. После dispatch неизвестный outcome удерживает резерв до сверки; автоматической переотправки того же логического вызова между попытками нет. Реальные платежи, клиентские тарифы и пополнение здесь не реализованы.

- [ ] Проверить подключение после перезапуска API и worker; выполнить настоящий короткий запрос к выбранной модели.
- [ ] Без согласия на изображения записать 15–30 секунд, остановить, просмотреть и скачать файл; убедиться, что live-анализ не запускался.
- [ ] Проверить отказ в доступе к камере, запись без микрофона, выключение устройства после остановки и сохранение файла после ошибки загрузки.
- [ ] С согласием включить live-наблюдение на простом видимом действии; сверить наблюдения с происходящим. Проверить восстановление после краткого сбоя сети и отсутствие новых кадров после остановки.
- [ ] Сохранить запись в инструкции, дождаться `ready`, отдельно разобрать её фрагмент без речи и проверить кадры-основания, пропуски действий и приблизительные интервалы.
- [ ] Проверить добавление к существующим шагам, подтверждённую замену, сброс отметок проверки и отказ устаревшему предложению после правки рабочей версии.
- [ ] При необходимости отдельно проверить локальную расшифровку и облачные шаги по речи; затем пройти проверку мастером и публикацию.
- [ ] Зафиксировать браузер/устройство, длительность, итоговые состояния, число найденных/пропущенных действий и затраты без ключей, изображений и закрытого содержания.

Ближайшая локальная приёмка — физическая камера, устойчивость к обновлению страницы/сбоям и несколько рабочих записей с ручным эталоном. Для серверного пилота команды отдельно нужны PostgreSQL, конкурентные workers, удалённый CI, backup/restore, обычный API-профиль с учётом затрат и проверка целевых мобильных устройств.

## Локальная проверка команд по реестру кадров

Для новых upload-сеансов доступно сочетание `VISUAL_ACTION_EVIDENCE=1`, `VISUAL_SHORT_ACTION_COVERAGE=1`, `VISUAL_FRAME_GROUNDING=1`. На этой машине оно включено; в `.env.example` экспериментальные флаги выключены. После изменения перезапустите API и worker. Режим фиксируется в сеансе и задании, поэтому старые анализы не переключаются на другую схему при перезапуске.

Модель возвращает реестр состояний и подтверждения условий действия в том же ответе. Сервер проверяет их согласованность и выводит фазы из реестра. В этом режиме дополнительные автоматические уточнения отключены: неясное действие требует просмотра человеком. Пределы кадров, размера запроса/ответа, обращений и денег остаются прежними. Форма получает `automatic_refinements=false` и показывает соответствующий план. Это не независимая проверка истинности изображения. Реализация и локальные проверки: [27. Проверка команд по кадрам](27-frame-grounding.md).
