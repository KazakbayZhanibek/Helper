# Первый пакет по результатам аудита: воркер и блокировки

Реализованы пункты 1–4 и 7 предложенного плана. Изменение уменьшает нагрузку на БД и время удержания блокировок; качество распознавания действий этим пакетом не измерялось. Новых обращений к ИИ — 0. Настройки OpenRouter и бюджетные пределы не менялись.

## Что изменено

- Обычный `JobContext.check()` выполняет один SELECT без явной блокировки строки, не чаще раза в 0,5 секунды. Проверка членства включена в запрос через EXISTS. Продление lease происходит отдельным условным UPDATE раз в 15 секунд. Задание с другим токеном, отменённое задание и отозванный доступ не получают продление.
- Перед внешним вызовом/процессом `check_dispatch()` сбрасывает кеш. Бюджетный транспорт вызывает эту проверку до отметки об отправке: отмена освобождает только ещё не отправленный резерв. `commit_guard()` по-прежнему блокирует строку задания и проверяет актуальные разрешения внутри транзакции записи.
- Цикл команды `processing_worker` переживает ошибки очистки и отдельной итерации. Ошибка очистки не мешает взять задание, повтор очистки назначается через минуту. После ошибки итерации есть пауза минимум 1 секунду. `--once` завершается с ошибкой, если итерация неуспешна. Сообщения исключений, которые могут содержать исходные данные/ключи, в лог не выводятся.
- В очистке старых каталогов `derived/` используется пакет до 50 кандидатов и два запроса защиты ссылок/lease на пакет вместо запросов на каждый каталог. Сохраняются каталоги, на которые ссылается любой из четырёх путей MediaAsset: видео, оригинал, аудио, миниатюра. Сохраняются каталоги действующих попыток. Обход ограничен 500 записями за проход. Это оптимизация конкретного участка maintenance, а не обещание постоянного числа запросов для всей очистки.
- Добавлена индексированная UUID-колонка `ProcessingJob.visual_session_id`, заполненная из старого JSON. Поиск для отмены, очистки и лимита live-заданий переведён на неё. JSON сохранён для истории и контракта задания; несовпадение колонки и payload отклоняется при обработке. Проверки организации, владельца и источника остаются. Добавлен индекс `VisualSession(state, expires_at)`.
- JPEG-декодирование и подготовка пакета загруженного видео выполняются до блокировки организации. Камера тоже декодирует до транзакции, затем повторно проверяет доступ, состояние сеанса, порядок, время кадра и идемпотентность. Проверка квоты, создание записей и файлов остаются защищены блокировкой. Добавлен отдельный замер `frame_decode`.

## Проверки

Полный серверный прогон: **1307 passed**, 54,31 с. Целевая проверка нового пакета и связанных модулей: **134 passed**, 12,24 с. Django system check и проверка отсутствующих миграций прошли. Интерфейс не менялся; production-сборка при перезапуске проверяется штатным launcher.

Новые тесты подтверждают:

- первый poll — один SELECT; 100 повторов в пределах интервала — ноль запросов; heartbeat — SELECT + UPDATE;
- немедленную остановку перед отправкой при отмене, смене lease, удалении задания, отключении пользователя/членства/организации/инструкции/источника;
- сохранение строгого commit guard и освобождение только неотправленного резерва;
- продолжение работы после ошибок очереди/очистки без раскрытия текста исключения;
- два запроса на проверку 40 старых каталогов, сохранение всех типов ссылок и активного lease;
- заполнение новой колонки, наличие обоих индексов, декодирование вне транзакции и отсутствие записи кадров при отмене во время декодирования.

Локальная миграция заполнена для **40 заданий**. Сравнение с резервной копией подтвердило неизменность инструкций, рабочих шагов, опубликованных версий, 468 кадров, 36 предложений, 41 записи расходов, 54 бюджетных счетов и всех прежних полей 46 заданий. PostgreSQL-конкурентность в этой сессии не проверялась: текущая рабочая база — SQLite, один последовательный worker.

Отчёты находятся локально в `artifacts/test-results/worker-package-backend.txt`, `worker-package-targeted.txt`, `worker-package-migration.json`. Резервная копия `worker-package-before.sqlite3` содержит частные данные и исключена из Git.

## Что остаётся из аудита

Следующий продуктовый пакет: явный повтор неудавшихся окон с новым бюджетным резервом, сохранение корректных действий при ошибке отдельного наблюдения, применение выбранных шагов и устранение тупика с лимитом 30 шагов. Накопление сохранённых кадров требует отдельной политики хранения с учётом опубликованных версий.

Параллельные вызовы, счётчик квоты кадров, перенос файловых записей из-под блокировки, изменение FFmpeg-лимитов/окружения и упрощение реестра протоколов в этот пакет не входят. Удалять старые протоколы до миграции сохранённых результатов нельзя.

В полном репозитории есть автоматические тесты и ограниченные сравнения на реальных роликах. Замечание об отсутствии тестов относилось к переданным архивам. При этом репрезентативный размеченный набор из 10–20 процессов ещё нужен; прохождение инженерных тестов не доказывает точность распознавания.
