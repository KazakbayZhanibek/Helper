# Один проект, два простых интерфейса

Одна база инструкций, видео и пользователей; два интерфейса внутри одного сайта. Это позволяет мастеру исправить один оригинал и показать новичку опубликованную версию, не синхронизируя два независимых сайта.

## Интерфейс мастера

Основной путь: «Записать или загрузить видео» → «Проверить шаги» → «Опубликовать». На первом экране только запись, загрузка и недавние инструкции. В проверке рядом находятся фрагмент видео, реальные фото и короткое объяснение действия. Непонятные места собраны в отдельный список вопросов, на которые мастер отвечает или снимает дополнительный фрагмент. Технические сведения ИИ раскрываются по запросу. Лимит расходов виден до запуска, расход — во время работы.

## Интерфейс новичка

Основной путь: «Найти задачу» → «Открыть шаг» → «Посмотреть и повторить» → «Следующий шаг». Один шаг на экране, крупные фото, кнопка просмотра соответствующего движения и ясный текст: что делаем, как, какой видимый результат получаем. Переход к исходному видео остаётся доступным. Новичок видит только опубликованную версию; черновики и незавершённые догадки ИИ ему не показываются.

## Порядок реализации

1. Стабилизировать обработку: фиксированный провайдер/модель, сохранение результата каждого окна, понятные ошибки, измерение времени и расходов. OpenRouter добавляется как сменный адаптер; выбор провайдера не меняет права, видео и публикации.
2. Провести одинаковый тест на нарезке, замесе, сборке и работе с инструментом. Для каждого ролика мастер составляет список реальных действий и отмечает отсутствующие в кадре сведения. Зафиксировать общий бюджет заранее; один прогон без автоматического каскада моделей.
3. Проверять долю сохранённых реальных действий, число выдуманных действий/деталей, правильность фото и таймкодов, понятность повторения процесса. Отдельно измерять подготовку видео, ожидание модели, валидацию и стоимость. Успешная JSON-валидация не равна правильному распознаванию.
4. Упростить стартовый экран мастера и проверку черновика, сохранив существующие API и права. Затем выделить пошаговый просмотр новичка на той же опубликованной версии.
5. Проверить оба пути на телефоне и компьютере: загрузка/запись → проверка → публикация → просмотр новичком. Проверить длинные названия, медленное соединение, прерванный анализ и восстановление.

## Условия приёмки пилота

Нет критических выдуманных действий; все обязательные этапы отмечены как показанные либо явно отсутствующие. Каждый показанный шаг связан с подходящими фото и фрагментом видео. Человек без пояснений разработчика понимает порядок и способ выполнения. Непоказанные числа, усилия, температура и материалы не достраиваются из общих знаний модели. Публикация требует проверки мастера. Скорость и качество считаются улучшенными только по сравнению на одном и том же наборе видео в одинаковом бюджете.

Этот документ — план. Разделение интерфейсов ещё не реализовано; текущий редактор и просмотр сохраняются.
