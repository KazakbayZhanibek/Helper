# Экраны и взаимодействие

[К полному плану](00-overview.md)

## Карта страниц

| Экран | Маршрут | Кому доступен |
|---|---|---|
| Вход | `/login?next=...` | Всем; next только относительный безопасный путь |
| Принятие приглашения | `/invite/:token` | По действующему одноразовому приглашению |
| Восстановление | `/password-reset` и `/password-reset/:token` | Всем, с нейтральным ответом |
| Библиотека | `/o/:org/instructions` | Участники организации |
| Новая инструкция | `/o/:org/instructions/new` | Author, reviewer, admin |
| Обработка | `/o/:org/instructions/:id/processing` | Author, reviewer, admin |
| Редактор | `/o/:org/instructions/:id/edit` | Авторские роли; только изменяемый черновик |
| Проверка | `/o/:org/instructions/:id/review` | Reviewer, admin |
| Чтение | `/o/:org/instructions/:id` | Все активные участники; только текущая публикация |
| Версии | `/o/:org/instructions/:id/versions` | Авторские роли |
| Участники | `/o/:org/members` | Admin |
| Настройки | `/o/:org/settings` | Admin |
| Сообщения о проблемах | `/o/:org/feedback` | Author, reviewer, admin |

Пилотная авторизация закрытая. Открытая маркетинговая страница и самостоятельная покупка тарифа в этот этап не входят.

## Общие правила интерфейса

- Навигация: название организации, «Инструкции», авторские разделы по роли, меню профиля. Читателю не показывать недоступные действия, но права всегда повторно проверяет сервер.
- Состояние и действие выражать словами, не только цветом. «Черновик», «На проверке», «Опубликовано», «Скрыто», «Ошибка обработки» имеют разные тексты и значки.
- У каждого запроса: загрузка, успешное состояние, пустое состояние, ожидаемая ошибка и возможность повторить. Ошибка сети не должна выглядеть как пустая библиотека.
- Основной язык RU; строки хранятся отдельно от компонентов, чтобы позднее добавить KK. Контент инструкции имеет свой язык.
- Пользовательские заголовки и тексты выводить как текст. В D1 нет произвольного HTML/Markdown, который может исполняться.
- Для опасного удаления показывать конкретный объект и последствия; обычное сохранение не требует модального подтверждения.
- Пустое поле получает пример и объяснение, а не только placeholder. Ошибка расположена рядом с полем; фокус переходит к первой ошибке.
- Даты отображать в часовом поясе пользователя; исходные события хранить UTC. В пилоте по умолчанию Asia/Almaty.

## S01 Вход и приглашение

Вход: email, пароль, показать/скрыть пароль, «Войти», «Забыли пароль». После ошибки не сообщать, существует ли адрес. Сохранить безопасный next через полный цикл входа, чтобы QR-код не потерял целевую инструкцию. Не отправлять next на внешний домен.

Приглашение: название организации, назначенная роль, адрес email, имя и установка пароля для нового пользователя. Существующий пользователь сначала входит под тем же адресом. При несовпадении адреса — понятное объяснение и возможность сменить аккаунт. Просроченная/отозванная ссылка не раскрывает список участников; текст: «Приглашение больше не действует. Попросите администратора создать новое».

Восстановление: всегда одинаковое подтверждение отправки. Если SMTP недоступен в локальной разработке, письма видны только в безопасном dev-инструменте; production не выводит reset token в журнал.

## S02 Библиотека

Карточка: название до двух строк, цель до 160 символов, язык, дата публикации, автор, обложка и количество шагов. Обложка декоративная; информация не должна зависеть от её наличия. Сортировка — сначала недавно опубликованные. Пагинация 20 элементов, серверная.

Читатель видит только публикации. Авторские роли дополнительно имеют вкладки «Опубликованные», «Черновики», «На проверке», «Скрытые». Поле поиска и фильтр языка сохраняются в URL. Запрос поиска выполняется после 300 мс паузы; отменять старый запрос, чтобы устаревший ответ не заменил свежий.

Пустая библиотека автора: «Загрузите первое видео и соберите инструкцию». Пустая библиотека читателя: «Здесь появятся инструкции после публикации». Пустой поиск: показать запрос, сброс фильтров, предложение попробовать другое слово. Не показывать чужие заголовки в подсказках.

## S03 Создание и загрузка

Поля: название 3–120 символов; цель 10–600 символов; язык `ru`, `kk`, `mixed`; файл; подтверждение права использовать запись. Подтверждение не заменяет договорённость с владельцем, но сохраняет факт действия пользователя.

До начала: показать лимит 500 MiB/10 минут, формат, совет «Произносите вслух названия действий и предметов». Проверить размер локально; сервер повторяет проверку. При неподходящем расширении — конкретный текст, а не «Что-то пошло не так».

Загрузка D1 — один поток HTTP с progress через XHR. Разрыв не возобновляется с середины: явно предложить выбрать файл и загрузить заново. После успешной передачи файл уже на сервере; закрытие страницы не останавливает обработку. Не обещать фоновую загрузку после закрытия мобильного браузера.

Во время передачи: имя, размер, фактический процент отправленных байтов, «Отменить». При отмене запрос прерывается и вызывается отмена upload session; повторная отмена безопасна. Уход со страницы при незавершённой передаче вызывает предупреждение браузера.

После передачи: «Файл загружен. Подготавливаем просмотр». Ответ с URL инструкции позволяет перейти в библиотеку. Повторное нажатие не создаёт второй объект благодаря Idempotency-Key.

## S04 Обработка

Стадии: «Ожидает обработки», «Проверяем файл», «Готовим видео», «Распознаём речь», «Составляем шаги», «Черновик готов». Процент передачи не переносится на обработку. Показывать длительность ожидания и кнопку «Перейти в библиотеку»; оценку оставшегося времени добавить только после накопления замеров.

Polling каждые 3 секунды, после минуты — каждые 10; при скрытой вкладке — каждые 30. Прекратить при финальном состоянии, отмене или выходе. Ошибка polling не меняет job на failed.

Ошибка: понятное объяснение, код для поддержки, действие «Повторить» при разрешённом повторе, «Разметить вручную» при готовом видео. При отсутствии аудио — «В записи нет речи. Можно добавить шаги вручную». Для отключённого внешнего провайдера — «Автоматическое составление шагов пока не подключено».

## S05 Редактор

На desktop: видео слева, шаги справа, сверху название и статус сохранения; расшифровка открывается отдельной вкладкой. На телефоне сначала видео, затем список; редактор на телефоне работает, хотя основная редактура предполагается на компьютере.

У шага: номер, заголовок 3–120 символов, описание 1–2000, начало и конец в `мм:сс.д`, кнопка «Взять текущее время», фрагменты-источники, пометка происхождения `ИИ/вручную`, отметка «Проверено». Максимум 30 шагов. Порядок задаёт человек; перестановка не меняет таймкоды автоматически. Кнопки «Выше/Ниже» доступны вместе с drag-and-drop.

Добавление: после выбранного шага, начало — текущее положение видео, конец — начало + 5 секунд, ограниченное длительностью; если интервал невозможен, поле требует выбора. Удаление шага требует подтверждения только при непустом содержимом. Разделение и объединение — после D1; в D1 делаются обычным добавлением/правкой.

Сохранение всей рабочей версии — debounce 1500 мс и явная кнопка «Сохранить». Сначала отправить последнюю локальную ревизию, потом очистить dirty state только после ответа с новой. Несколько параллельных autosave не отправлять: очередь на клиенте из одного запроса и последнего накопленного состояния. При проблеме сети сохранять форму в памяти, показывать «Изменения ещё не сохранены», блокировать уход стандартным предупреждением. Не хранить производственные тексты в localStorage без отдельного решения.

Конфликт 412: остановить autosave, показать «Инструкцию изменили в другом окне». Дать сохранить локальный текст в доступном для копирования диалоге, загрузить актуальную версию или вернуться к сравнению. Не делать автоматический overwrite. В D1 нет совместного редактора реального времени.

Правка любого содержательного поля шага снимает его отметку проверки. Правка расшифровки не меняет автоматически текст шагов; отмечает связанные источники как требующие повторного просмотра. Человек решает, обновлять ли шаг. Повторная генерация создаёт предложение отдельно и не заменяет ручную работу.

## S06 Проверка и публикация

Автор нажимает «Отправить на проверку», после подтверждённого сохранения. Сервер валидирует заголовок, цель, шаги, границы времени и готовность видео. Версия получает review revision и блокируется. Автор может отозвать запрос проверки; это инвалидирует предыдущие отметки проверяющего и возвращает черновик.

Проверяющий видит точную версию, источник и список шагов. Для публикации каждый шаг должен быть проверен, все блокирующие замечания закрыты, а общие пункты подтверждены: порядок действий, терминология, достаточность пояснений, актуальность и отсутствие лишних чувствительных данных. Эти флажки не являются доказательством просмотра видео сами по себе — журнал отражает только подтверждение человека.

«Вернуть на доработку» требует причины 10–2000 символов. «Опубликовать» указывает номер версии и факт замены текущей. При изменении ревизии с момента открытия сервер отклоняет публикацию. Двойной клик публикует один раз.

## S07 Чтение

Название, цель, номер и дата версии, проверяющий, шаги, видео. Выбор шага перематывает к start_ms; воспроизведение запускается только по действию пользователя. Режим «Этот шаг» останавливает видео у end_ms приблизительно с точностью браузерного проигрывателя; нельзя обещать покадровую точность. Есть обычное полное воспроизведение.

Изменение текущей публикации не переключает просмотр посреди работы. Баннер: «Доступна новая версия», кнопка обновления; серверный ответ указывает открываемую version_id. Отзыв или удаление проверяются при следующем запросе; уже полученные пользователем байты нельзя отозвать.

Ссылка QR содержит только путь инструкции, не токен доступа. После входа возвращает к ней. Старый QR работает после новой публикации. Скрытая инструкция показывает «Инструкция временно недоступна. Обратитесь к ответственному» без старого содержимого.

«Сообщить о проблеме»: категория «Неточно/Устарело/Не работает/Другое», шаг необязателен, текст 10–2000. Сообщение фиксирует version_id; повторная отправка не дублируется.

## S08 Участники и настройки

Администратор приглашает по email, выбирает одну роль, видит статус. Может отозвать приглашение, изменить роль или отключить участника. Последнего активного admin нельзя понизить или отключить. Изменение своей роли показывает последствия до запроса.

Настройки пилота: название, допустимый режим обработки, лимиты и использование, контакт ответственного. Внешний провайдер настраивается оператором сервиса; ключ не показывается в браузере администратора компании.

## S09 Версии, отзыв и удаление

Список версий показывает номер, автора, проверяющего, дату и статус. Просмотр старой версии доступен авторским ролям; читатель по произвольному version_id не получает историю. Возврат к старому содержимому — копия в новый черновик с новым номером и обычной проверкой.

Отзыв публикации обязателен при серьёзной ошибке: причина, подтверждение и исчезновение из поиска. Удаление инструкции доступно admin; текст предупреждения перечисляет видео, шаги и историю. Сначала объект скрывается, потом запускается очистка. Если очистка не завершилась, администратор видит статус и обращение к оператору, а не ложное «Всё удалено».

## Проверка интерфейса

Клавиатура, видимый фокус, label для каждого поля, тексты ошибок для screen reader, управление модальными окнами, отсутствие зависимости только от перетаскивания и цвета. Проверить 360/390/768/1440 px, Safari iOS, Chrome Android и desktop. Субтитры из проверенной расшифровки полезны, но сам редактор должен работать и до её появления.
