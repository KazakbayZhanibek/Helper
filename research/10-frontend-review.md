# Независимая проверка frontend

Агент №10 · 29 октября 2026. Проверены `api.ts`, `Editor.tsx`, `Reader.tsx`, `Library.tsx`, `Auth.tsx`, `App.tsx`, `components.tsx`. Код приложения не изменялся. Проверка основана на исходниках и TypeScript-компиляции; браузерную проверку выполняет основной агент.

## Найденные ошибки

1. **P2 — устаревшая страница может попасть под новый фильтр.** В `Library.tsx`, функция `more`, запрос следующей страницы не имеет AbortController или идентификатора набора фильтров. Воспроизведение: при библиотеке больше 20 записей нажать «Показать ещё», изменить поиск или язык до ответа. Если основная выдача нового фильтра приходит раньше старого `more`, старые карточки дописываются к новой выдаче и подменяют cursor. Основная загрузка корректно отменяется, но пагинация — нет. Исправление: отменять и/или игнорировать `more` из предыдущего поколения фильтров. Передано root и frontend_implementation.

2. **P2 — истёкшая сессия оставляет пользователя в закрытом интерфейсе.** `App.tsx` проверяет `/auth/me` только при монтировании. Другие API 401 не сбрасывают `session`. Кнопка выхода также ожидает успешный POST logout, но с истёкшей сессией сервер возвращает 401; catch сохраняет прежнюю сессию. Воспроизведение: войти, истечь/отозвать cookie-сессию, выполнить API-действие, нажать выход. Форма входа появляется только после полной перезагрузки. Минимальное исправление: считать 401 logout уже завершённым выходом; лучше добавить восстановление входа с сохранением несохранённой формы в памяти. Передано root и frontend_implementation.

3. **P2 — форматирование времени создаёт недопустимые секунды.** `Editor.tsx:8` округляет секунды отдельно от минут. Реально выполненный Node-проверкой пример: `formatMs(59950)` и `formatMs(59999)` дают `00:60.0`, а `parseMs` возвращает NaN. `formatMs(119999)` даёт `01:60.0`. Это случается при выборе текущего времени у границы минуты либо загрузке сохранённых миллисекунд. Исправление: сначала округлять общее число десятых долей секунды, затем делить на минуты/секунды; либо сохранять точные миллисекунды. Передано frontend_implementation.

## Доступность и небольшие замечания

- `Dialog` использует native `<dialog>` и видимый `<h2>`, но не связывает заголовок через `aria-labelledby` и не даёт `aria-label`. Нужен доступный name диалога (например `useId` для заголовка).
- Проверки полей редактора отображаются общим списком без `aria-invalid`, привязки ошибки к полю и перевода фокуса к первой ошибке. Поля подписаны, ошибки имеют `role=alert`; для полного UX-критерия из `docs/02-ux.md` нужна точечная связь.
- На чтении есть общая отметка проверки, но значение `version.published_by` не отображается. В плане требуется показывать проверяющего.

## Что проверено положительно

- CSRF читается из cookie после ротации входа; fetch использует same-origin credentials.
- В редакторе один запрос сохранения защищён `inFlight`. Во время сохранения поля блокируются, поэтому обычная правка не перетирается ответом предыдущего autosave.
- Конфликт 412 останавливает сохранение и сохраняет форму в памяти; есть диалог для копирования и подтверждение перед заменой актуальной версией.
- Отправка на проверку сначала ожидает сохранение и использует новый ETag.
- Публикация имеет стабильный idempotency key для повторения того же запроса, сервер проверяет полномочия.
- Пользовательский текст выводится React-текстом, нет raw HTML/localStorage для содержимого.
- Выбор шага в reader ставит паузу и перематывает; воспроизведение начинается явным действием пользователя.
- Новый snapshot не подменяет уже открытый просмотр: появляется уведомление.
- У управления шагами есть доступные кнопки вверх/вниз/удалить, помимо обычных текстовых полей.
