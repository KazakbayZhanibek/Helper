# Зрение: загруженное видео и живая камера

Все маршруты после `/api/v1/orgs/{org}`, только author/reviewer/admin. Все изменения защищены session+CSRF. Облако получает реальные JPEG, только после `consent_images:true`, при включённых global+organization флагах и настроенном провайдере. Прямой API требует серверный ключ, локальный Codex-тест использует существующий вход ChatGPT. Демонстрационной подмены результатов нет.

## Возможности

`GET /visual-capabilities` возвращает available/configured/provider/model/reason/external, live_supported/uploaded_video_supported, limits и budget. Limits: session_duration_ms=600000, max_frames=300, max_frame_bytes=524288, max_dimension=960, min_frame_interval_ms=1000, max_analysis_frames=12, analysis_interval_ms=8000, max_analysis_calls=60, max_window_ms=60000, overview_window_ms=30000, refinement_window_ms=15000. Available означает готовую конфигурацию, не гарантию доступа аккаунта.

Budget: mode (`usd/subscription_calls/local_calls/unavailable`), currency, default_max_calls/max_calls, default_max_cost_microusd/max_cost_microusd, call_upper_bound_microusd, pricing_version. Денежные поля null для Codex/локального Ollama; это не нулевая стоимость. Проверенный денежный профиль только OpenAI gpt-5.4-mini. Неизвестные тарифы, включая NVIDIA, блокируют фактический запрос.

## Живая камера

1. `POST /instructions/{id}/visual-sessions` `{consent_images:true}`, If-Match + Idempotency-Key → 201 session. Допускается инструкция без исходного видео. Предварительно браузер запрашивает доступ к камере явным действием пользователя.
2. `POST /visual-sessions/{id}/frames`, body **binary JPEG**, Content-Type `image/jpeg`, `X-Frame-Sequence` integer начиная с 1, `X-Timestamp-Ms` integer относительно подключения live-наблюдения после создания сеанса; этот отсчёт отделён от начала MediaRecorder-записи, `Idempotency-Key` → 201 frame. Повтор точно того же кадра → 200. Клиент сохраняет один ожидающий JPEG, его номер, время и ключ до подтверждения сервера; после сетевого сбоя повторяет тот же запрос, включая случай потерянного ответа. Следующий номер выдаётся только после подтверждения. Ограничения выше; сервер декодирует и повторно кодирует JPEG, удаляя metadata. Сервер допускает не чаще одного нового кадра в секунду; интерфейс отправляет раз в 2 секунды.
3. `POST /visual-sessions/{id}/analyze` `{}`, Idempotency-Key → 202 стандартный ProcessingJob.kind=analyze_live. Берётся не более 12 последних кадров; source IDs фиксируются в job. Одновременно только одно такое задание для инструкции, не чаще 8 секунд. При активном задании 409 JOB_ALREADY_RUNNING.
4. `GET /visual-sessions/{id}` → session с `observations` (последние 5 VisualProposal) и `frames` (последние 12). `POST /visual-sessions/{id}/cancel` `{}` → 200 session, отменяет ожидающие задания и блокирует позднюю запись результата. При остановке камеры клиент вызывает cancel; сохранение полной записи идёт отдельно через стандартную загрузку видео.

Session: `{id,instruction_id,asset_id:null|UUID,mode:'live'|'upload',state:'active'|'completed'|'cancelled'|'expired',base_working_revision,created_at,expires_at,frame_count,frames:[frame],observations:[proposal]}`.

Frame: `{id,sequence,timestamp_ms,width,height,url}`. URL `/api/v1/orgs/{org}/visual-frames/{id}` возвращает защищённый JPEG. Никаких публичных URLs или storage keys.

Live-предложения содержат `preliminary:true,can_apply:false`. Это наблюдения по выборке кадров, они никогда не применяются к рабочим шагам. После остановки MediaRecorder клиент загружает полную запись и запускает **новый** анализ загруженного видео. Никакой автоматической привязки таймкодов камеры к записи.

## Загруженное видео

- `POST /instructions/{id}/visual-proposals` `{consent_images:true,scope:'full'|'window',max_ai_calls,max_cost_microusd}`, If-Match + Idempotency-Key → 202 ProcessingJob.kind=analyze_video. Звук не обязателен. Без scope/границ default full: вся запись до 10 минут. В full нельзя задавать start_ms/end_ms. Для совместимости переданные границы без scope выбирают window; window допускает start_ms/end_ms внутри записи до 60 секунд.
- Полный режим создаёт последовательные overview-окна по 30 секунд и до 12 реальных кадров в каждом; сначала выполняются все overview. Неясные окна (uncertain_action/occluded_view/insufficient_evidence/missing_parameters или без шагов) могут получить один уровень уточнений до 15 секунд / 12 кадров при оставшемся бюджете. Рекурсивного дробления нет.
- Перед enqueue preflight проверяет бюджет всей baseline. Слишком мало max_ai_calls → 422 AI_BUDGET_TOO_SMALL, общие квоты → 422 AI_BUDGET_EXCEEDED. Preflight не удерживает бюджет всей очереди; каждый вызов затем проходит отдельный атомарный резерв. По умолчанию сеанс: 30 вызовов, для USD $2; максимум 60/$5. Параллельный расход общего бюджета может остановить анализ позже.
- VisualAnalysisWindow сохраняет parent, ordinal, start/end, state (pending/running/completed/failed), frame_ids, manifest, content и error_code. Готовый checkpoint не отправляется снова. Окно с неизвестным отправленным запросом не повторяется автоматически после потери worker. UI получает прогресс, сохранённые ответы и непросмотренные диапазоны.
- Уточнения заменяют обзор родителя только если все дочерние окна завершены, дали шаги и не содержат признаков неопределённости. Иначе сохраняется исходный обзор с предупреждением. Больше 30 итоговых наблюдений сохраняются целиком, но их применение к одной инструкции запрещено.
- `GET /instructions/{id}/visual-proposals` → `{items:[proposal]}` newest-first, максимум 20; содержит только mode upload.
- `GET /instructions/{id}/visual-proposals/{id}` → proposal.
- `POST /instructions/{id}/visual-proposals/{id}/apply` `{confirm_replace:true,mode:'replace'|'append'}`, If-Match + Idempotency-Key → стандартная WorkingCopy; stale → 409. Серверный default при отсутствии mode — replace. Интерфейс явно отправляет выбранный режим и при существующих шагах предлагает append; append сохраняет текущие шаги и добавляет новые, максимум 30 всего. В обоих режимах отметки проверки сбрасываются. Только предложения из загруженного видео. Применение не публикует материал.

Proposal: `{id,instruction_id,session_id,base_working_revision,provider,model,created_at,applied_at,preliminary,can_apply,stale,window_start_ms,window_end_ms,schema_version:'2',language,steps:[{title,description,start_ms,end_ms,evidence_frame_ids}],warnings:[{code,message}],frames:[frame],analysis?}`. Времена вычисляет сервер из кадров, их точность ограничена выборкой; всегда warning approximate_timing. Для заявления о действии нужны минимум два упорядоченных кадра. Все новые шаги требуют проверки человеком. Загруженные кадры хранятся как evidence. Job.result → `{visual_session_id,visual_proposal_id?,analysis}`. Analysis: scope, windows_total/windows_completed, refinement_windows/refinements_completed, coverage_complete, sampling=discrete_frames, unprocessed_ranges, windows (id/start/end/kind/state/error_code), budget (mode/currency/max_calls/calls_used/max_cost_microusd/reserved_microusd/spent_microusd/unknown_calls). Coverage complete означает завершение всех обзорных окон, не непрерывное наблюдение каждого кадра.

Схема ответа модели v2: title/description/evidence_frame_ids без свободных таймкодов. Строгая локальная проверка ID, порядка и принадлежности session. Реальная картинка идёт base64 image_url в Chat Completions без инструментов. Локально выбран Codex/gpt-6-luna через подписку; производственный путь — прямой API. OpenAI использует `STEP_DRAFT_API_KEY` и `store:false`. NVIDIA-адаптер сохранён, но денежный барьер блокирует его до проверки тарифов/usage. NVIDIA-запрос задаёт `max_tokens`, `stream:false`, `reasoning_effort:none` и `json_schema`; ключ одного провайдера не используется для другого. Неописанные движения между кадрами не считаются установленными фактами, числа/материалы/параметры нельзя додумывать.

## Хранение и ограничения

Кадры на сервере доступны только участникам организации с правом авторской работы через защищённый API.

Live-session активна максимум 10 минут, не больше 300 кадров по 512 KiB, окно анализа максимум 12 кадров и максимум 60 вызовов ИИ за сеанс, включая повторы; минимум 8 секунд между вызовами. Дополнительно ledger по умолчанию ограничивает сеанс 30 обращениями, организацию 100/день и 2 000/месяц UTC, платформу 500/день UTC. Экономный live 30 секунд / 20 вызовов и кеш разных запусков пока не внедрены. Не больше 3 одновременно активных камер и 512 MiB сохранённых кадров на организацию. Worker вызывает ограниченную очистку примерно раз в минуту; доступен и отдельный запуск команды `cleanup_visual_sessions`. Завершённые/отменённые/истёкшие live frames удаляются не ранее чем через 1 час после expires_at; текст предварительных наблюдений остаётся для просмотра. Применённые uploaded evidence сохраняются вместе с инструкцией, кадры неиспользованных uploaded sessions очищаются через 7 суток от создания сеанса. Очистка ограничена порцией 50 сеансов и не удаляет сами сеансы, полную запись или текст предложений; без worker либо при активном задании фактическое хранение может быть дольше. Команда не удаляет файлы активного задания. Удаление/приостановка организации и отзыв доступа блокируют отправку и commit.


## Бюджет и неопределённые исходы

Перед каждым внешним вызовом резервируются квоты сеанса, организации (UTC-день/месяц), платформы (UTC-день); для проверенного USD-профиля — также деньги. Максимум одного запроса из 12 кадров gpt-5.4-mini резервирует $0,072696 по версии тарифов 2026-11-01; фактический расход считается по usage. Receipt фиксируется до проверки модельного JSON независимо от отмены/lease. До отправки возможен released, после отправки неизвестный исход удерживает полный резерв; логический `(job,call_key)` не переотправляется между попытками. Поздний достоверный receipt может закрыть unknown. Подробные лимиты и настройки — [setup](../docs/15-video-ai-setup.md#серверные-лимиты-ии).

## Проверка интеграции

Прямой API без ключа сообщает unavailable; Codex-тест проверяется отдельно через существующий вход подписки. Тесты используют реальные JPEG и извлечение кадров FFmpeg, подменяя облачный ответ. Они проверяют контракт и состояние, но не подтверждают качество визуального распознавания, доступность платной модели или работу физической камеры. Настройка и отдельный аппаратный/облачный checklist: [видео, камера и ИИ](../docs/15-video-ai-setup.md).
