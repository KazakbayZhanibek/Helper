# Реальные ASR и предложения шагов

API после `/api/v1/orgs/{org}` (только admin/author/reviewer):

- `GET /ai-capabilities` → `{asr:{available,configured,provider,model,reason},step_drafts:{available,configured,provider,model,reason,external},experimental_languages:["kk","mixed"]}`. Никаких ключей, endpoint или путей модели. `available` ASR означает проверенную конфигурацию, а окончательная готовность проверяется заданием. LLM проверяет наличие настроенной локальной модели без её загрузки.
- `POST /instructions/{id}/transcribe`, body `{}`, `If-Match`, `Idempotency-Key` → 202 ProcessingJob. Готовый source с audio обязателен. Не меняет рабочие шаги.
- `GET /assets/{id}/transcript` → `{id,asset_id,revision,language,provider,model,duration_ms,created_at,warnings,segments:[{id,ordinal,start_ms,end_ms,raw_text,text}]}`. Последняя immutable ревизия; 404 когда её нет.
- `POST /instructions/{id}/draft-proposals`, body `{transcript_id,transcript_revision,base_working_revision}`, `If-Match`, `Idempotency-Key` → 202 ProcessingJob. В payload job сервер фиксирует версии, клиент не может задать provider или origin.
- `GET /instructions/{id}/draft-proposals` → `{items:[proposal...]}` newest-first, максимум 20. Позволяет восстановить состояние после reload.
- `GET /instructions/{id}/draft-proposals/{proposal_id}` → proposal: `{id,instruction_id,transcript_id,transcript_revision,base_working_revision,provider,model,created_at,applied_at,stale,language,steps:[{title,description,start_ms,end_ms,evidence_segment_ids}],warnings:[{code,message}]}`.
- `POST /instructions/{id}/draft-proposals/{proposal_id}/apply`, body `{confirm_replace:true}`, `If-Match` + `Idempotency-Key` → 200 стандартная WorkingCopy. Отсутствие If-Match → 428, устаревшая рабочая копия или transcript → 409 STALE_PROPOSAL. Применение явно заменяет шаги, ставит origin=ai и обнуляет проверки. Публикация не вызывается.

Job сериализуется `media_pipeline.jobs.job_data`. Worker вызывает `ai_drafts.worker.process_job(job,context)` для `transcribe` / `draft_steps`, получает `{transcript_id,transcript_revision}` или `{proposal_id}` в job.result. Контекст предоставляет `stage`, `check`, `run(args,timeout)`; ошибки `media_pipeline.exceptions.ProcessingFailure` без исходного текста ответа провайдера.

Таблицы ai_drafts: immutable Transcript revision на asset, TranscriptSegment с UUID и ordinal, DraftProposal с исходной working revision и ссылкой на точную Transcript. ASR-перезапуск создаёт новую transcript revision, не перезаписывает старую. Каждый последующий apply проверяет последнюю ревизию. Новая расшифровка инвалидирует проверки зависимых рабочих шагов; опубликованная версия неизменна.

Конфигурация сервера: `ASR_BACKEND=whisper_cpp|faster_whisper|whisper`, `ASR_PYTHON`, `WHISPER_CPP_BINARY`, `ASR_MODEL_PATH` — только существующая локальная модель. Для whisper.cpp можно установить `ASR_NO_GPU=1`. `STEP_DRAFT_BACKEND=ollama|openai|nvidia`, `STEP_DRAFT_ENDPOINT`, `STEP_DRAFT_MODEL`. OpenAI использует `STEP_DRAFT_API_KEY`, NVIDIA — отдельный `NVIDIA_API_KEY`; ключи не взаимозаменяемы. Без настроек обработка отключена. Внешний endpoint требует одновременно `EXTERNAL_AI_ENABLED=1` и organization.external_ai_enabled. Ключи читаются только сервером. Автоматического скачивания, запасного внешнего провайдера, function calling и автоматического применения нет. Для облака available означает комплект настроек, окончательная проверка ключа происходит при выполнении задания.

Текущий выбранный режим: существующая на компьютере whisper.cpp small для ASR и NVIDIA API Catalog для шагов, `nvidia/nemotron-3.5-super-vl-120b-a12b` на `https://integrate.api.nvidia.com/v1`. NVIDIA-запрос использует `max_tokens`, `stream:false`, `reasoning_effort:none`, строгий `json_schema`. Альтернативный OpenAI-адаптер использует `max_completion_tokens`, `store:false`, strict Structured Outputs. Неподдерживаемый provider-схемой uniqueItems проверяется полным локальным валидатором. Отказ модели и оборванный ответ отклоняются. Вход ограничен 18 000 символами/300 фрагментами, результат — 8192 completion tokens, один вызов без скрытых повторов. Суточный реестр стоимости/бюджета пока не реализован.

Валидация: исходная JSON Schema, bounded JSON без duplicate keys, строгое совпадение evidence UUID с выбранной расшифровкой, последовательные ordinal, точные time bounds, отсутствие новых цифровых значений/единиц. Пересечения получают warning. Это не доказывает смысловую правильность: результат всегда требует проверки человеком.

Настройка, выбор провайдера и ограничения облачной/аппаратной приёмки: [видео, камера и ИИ](../docs/15-video-ai-setup.md). При наличии конфигурации облачный ключ ещё требует реальной проверки; баланс и доступность кредитов не определяются этим API приложения.
