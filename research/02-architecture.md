# Архитектурный разбор — агент 02

Дата: 29 октября 2026. Источники: документы 03–08 исходного проекта. Исходники Obsidian не изменялись.

## Вывод

Проект уже содержит достаточно строгие контракты для начала реализации. Минимальный полезный запуск — foundation и ручной редактор с сохранением в серверной БД. Это начало D0, не завершённый D0. ИИ не нужен для первого результата и по плану отключён по умолчанию.

## Первый runnable slice

1. React 19 + TypeScript + Vite: маршруты, библиотека, редактор, reader preview, клиент API с обработкой 401/403/412 и состоянием несохранённых изменений.
2. Django 5.2 + DRF: своя UUID User до первой миграции; Organization, Membership, Instruction, WorkingCopy, WorkingStep. Session auth, CSRF для login и unsafe requests, нормализованный 401, единый error envelope.
3. PostgreSQL для проверки транзакций и ограничений; SQLite допустим лишь как явно ограниченная локальная демонстрация, не доказательство правильности конкурентных операций.
4. Служебный seed создаёт собственную демонстрационную организацию, две роли и безопасный пример комплектации. Учётные данные только для локального демо.
5. Author: создать инструкцию → изменить цель/язык → добавить/удалить/переставить шаги → сохранить с If-Match → перезагрузить и получить тот же текст. Reader видит только текущий snapshot, никогда черновик.
6. Две вкладки: второй PUT со старым ETag получает 412; введённый текст остаётся на экране. Это полезный первый интеграционный тест, проверяющий риск потери данных.

Пока нет готового asset и медиаконтура, API публикации не должен обходить обязательный ready source. Можно реализовать UI review/reader на clearly-marked fixtures, сохранив разделение demo и серверного продукта.

## Контракты, которые нельзя упростить незаметно

- `/api/v1/orgs/{org_id}/...`, UUID, snake_case, integer milliseconds, UTC timestamps.
- Ответ ошибки: `error.code/message/field_errors/request_id/retryable/details`; X-Request-ID.
- Чужой объект или отсутствующая membership → 404; запрещённое действие в своей организации → 403; нет сессии → 401.
- `GET working-copy` возвращает `ETag: "wc-<uuid>-rN"`; отсутствие If-Match → 428, устаревший → 412. Каждая правка и review operation увеличивает revision.
- Новый шаг имеет `id: null`; сервер назначает UUID. Не принимать checked_by, published_by, origin=ai из тела клиента.
- Idempotency-Key для create/upload/retry/generate/publish/feedback/delete; повтор с иным payload → 409.
- Один открытый WorkingCopy на instruction; публикация закрывает его; новая версия начинается явным create-draft.
- Все связи tenant-сущностей должны согласовывать organization_id на уровне БД; serializer проверки недостаточно.

## Инварианты review и publish

Транзакция блокирует Instruction и WorkingCopy, повторно проверяет membership, роль, ETag, in_review, ready source, отсутствие удаления, обязательные поля, 1–30 шагов, интервалы, reviewer confirmations и отсутствие открытых blockers. Затем создаёт immutable PublishedVersion, content hash, следующий номер, обновляет current_version/search text и закрывает рабочую копию. Author не может публиковать или разрешать blocker. Правка шага сбрасывает подтверждение. Отзыв не возвращает предыдущую версию автоматически.

## Что отложить до следующего среза

- Реальный upload: quota reservation под row lock, streaming на закрытый диск, UUID paths, quarantine и SHA-256.
- Worker: job lease/heartbeat, независимый recovery, отмена и защитa от позднего результата. Redis не хранит источник истины.
- FFmpeg: без shell, ограничение процесса и сетевого ввода; playback через Nginx internal после проверки доступа, Range/HEAD/416.
- ASR и DraftProvider: отдельные адаптеры; только разрешённая расшифровка, никаких инструментов публикации. Proposal не перезаписывает working copy автоматически и проверяет обе ревизии.
- Backup/restore и deletion tombstones до реального пилота.

## Проверки первого среза

- Чужая организация не видна через все реализованные endpoints.
- Reader не читает рабочую копию и не вызывает mutation; отключённый участник теряет следующий запрос.
- Login и PUT без CSRF отклоняются.
- Несколько сохранений/перезагрузка не теряют текст; две вкладки дают один успех и один 412.
- Неверные интервалы и связанные чужие UUID не сохраняются частично.
- Frontend build/typecheck; клавиатура и layout на мобильной ширине; сообщения ошибок не подменяют успешное сохранение.

## Риски

Главные риски не в выборе UI библиотеки: tenant-утечка, потеря редакторских изменений, публикация не той ревизии, публичное медиа, гонки квоты/worker, и обещание готовности AI на фикстурах. Проверять их раньше визуального расширения. Подключённые дизайн-сервисы полезны для публичных/синтетических референсов; производственные видео и расшифровки не отправлять автоматически.
